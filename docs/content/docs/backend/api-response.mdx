# 接口响应约定

后端业务接口统一返回 JSON：

```json
{
  "code": 0,
  "data": {},
  "msg": "ok"
}
```

- `code`: 业务状态码，`0` 表示成功，非 `0` 表示失败。
- `data`: 业务数据。失败时通常为 `null`。
- `msg`: 响应消息。成功默认为 `ok`，失败时放错误原因。

前端请求逻辑以 `code` 判断业务是否成功。当前后端业务失败也会返回 HTTP 200，前端不要只依赖 HTTP 状态码判断结果。

接口连接失败、服务不可达、返回体不是约定 JSON 时，前端按网络或接口异常处理。

## 请求 ID 与访问日志

- 每个响应都会返回 `X-Request-ID`。客户端可传入由字母、数字、点、下划线、冒号或短横线组成且不超过 128 位的请求 ID；缺失或格式无效时由服务端生成 UUID。
- 同一个请求 ID 会写入结构化访问日志，并在用户端 AI 代理请求中传给上游，便于关联浏览器、API 和上游调用。
- 访问日志使用 JSON，包含 `request_id`、方法、路由模板、HTTP 状态、耗时、响应字节数和客户端 IP，不记录请求体、Cookie、API Key 或签名 URL。
- 批量生产、邀请邮件 Outbox、对象删除、文件维护和提示词同步等后台任务也使用 JSON 日志，统一包含 `component=worker`、`worker` 和 `event`，并按任务类型附带企业、任务、生产项、Outbox 或删除记录编号、尝试次数与耗时。
- Worker 错误只记录 `error_type` 和安全的业务关联字段，不记录 SMTP、对象存储、执行器或远程同步返回的原始错误文本，也不记录收件地址、对象键、访问令牌或签名 URL。

## 健康检查

- `GET /api/health` 与 `GET /api/health/live` 是进程存活检查，不访问数据库。
- `GET /api/health/ready` 是数据库就绪检查；数据库可用时返回 HTTP 200，连接失败或超过 3 秒时返回 HTTP 503。这是业务接口统一 HTTP 200 规则的明确例外。
- `GET /api/admin/operations/health` 仅管理员可访问，返回批量生产队列、邀请邮件 Outbox 和对象删除 Outbox 的等待数、失败数及过期租约数，并返回最近 24 小时生成任务的总数、运行中/成功/失败数、终态成功率、平均耗时和 P95 耗时。
- 管理员可在“系统设置 → 运维告警”配置各类积压、失败和过期租约阈值。阈值达到时响应中的 `alerts` 返回 `key`、当前值和阈值，整体状态为 `degraded`；单项阈值设为 `0` 时不告警。
- 队列积压和运维告警不会直接让 readiness 失败，避免探针重启进一步放大积压；外部告警系统应读取管理员健康摘要中的 `status` 与 `alerts`。
