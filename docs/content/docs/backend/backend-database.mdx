### organizations / organization_members

企业租户和成员关系表。一个用户可以加入多个企业，`users.organization_id` 只保存新会话默认/最近使用的企业。登录后的企业 API 请求携带 `X-Organization-ID`；浏览器原生图片、视频和下载请求无法自定义 Header，因此媒体 URL 使用 `organization` 查询参数携带企业 ID。后端中间件会逐请求校验企业状态和成员关系，再把企业上下文传给画布、媒体、模型任务和电商业务，多个浏览器标签页可各自保持独立企业上下文。

`organizations` 保存企业名称、唯一标识、状态、创建人和创建时间；仅服务端使用的 `batch_claim_cursor` 记录该企业最近一次领取批量生产项的顺序游标。`organization_members` 通过 `organization_id + user_id` 联合唯一索引关联成员，角色包括 `owner`、`admin`、`member`、`reviewer`。企业与成员关系均保存 `version` 乐观版本号；企业设置、成员角色、成员移除和所有权转移必须提交读取时版本，拒绝多个管理员基于旧页面静默覆盖。企业所有者可以转移所有权，管理员不能修改或移除所有者。

### organization_invitations / organization_email_outboxes / organization_audit_logs

企业邀请保存受邀邮箱、角色、状态、邀请人和过期时间；状态包括 `pending`、`accepted`、`revoked`、`expired`，查询和再次邀请时会先把过期记录原子标记为 `expired`。邀请与 `organization_email_outboxes` 邮件事件在同一事务创建，后台 Worker 通过租约原子领取并使用 SMTP 发送，失败后指数退避，进程退出或租约过期后可重新接管；接受、撤销或过期的邀请会取消尚未发送的事件。邀请接受时以待接受状态和过期时间为条件原子更新，再创建成员关系并切换默认企业，避免撤销与接受并发穿透。审计日志按企业记录成员、品牌、商品、SKU、批量任务和画布保存等操作，并与对应业务写入处于同一数据库事务，普通成员不可读取。

### brands

企业品牌规范表，按 `organization_id` 隔离，保存 Logo 的企业私有 `storageKey`、品牌色、字体、品牌语气、视觉规范和禁用词。企业内品牌名称使用联合唯一索引；Logo 文件引用与品牌保存处于同一事务。品牌使用 `version` 乐观版本号，保存和删除必须提交读取时版本，其他成员已保存新版本时拒绝静默覆盖或误删。

### products / product_skus

企业商品主数据表。`products` 保存 SPU 编码、品牌、类目、卖点、目标人群和状态；`product_skus` 保存 SKU 编码、规格属性、企业私有参考图 `storageKey` 和状态。SPU、SKU 编码均在企业内唯一，SKU 创建后不能变更所属商品；两张表均使用 `version` 乐观版本号和条件更新，保存和删除都必须提交读取时版本，拒绝基于旧版本的并发覆盖或误删。商品作为 SKU 聚合根，SKU 创建、更新或删除会在同一事务递增所属商品版本，因此旧商品列表不能级联删除其他成员刚变更的 SKU。品牌、商品或 SKU 已被商品主数据或批量生产历史引用时拒绝删除；写入、任务创建和删除会锁定相同父级记录，避免并发产生悬空引用。SKU 参考图引用与 SKU 保存处于同一事务，删除 SKU 或包含它的商品时同步释放引用，并从实际删除时间开始计算 24 小时文件回收宽限期。

### batch_production_jobs / batch_production_items / batch_production_snapshots

企业批量生产任务及任务项。创建接口要求客户端生成 `request_id`，并通过 `organization_id + request_id` 联合唯一索引保证超时重试、双击和代理重放只创建一次任务；`request_hash` 保存规范化名称、品牌、模板和商品集合的 SHA-256 摘要，同请求号只有摘要一致时才返回已有任务，不同内容会返回冲突。每个任务还保存仅服务端可见的随机 `archive_token`，用于隔离 Worker 归档文件命名空间。幂等查询在商品和 SKU 展开前完成，成功响应丢失后的重试不会受后续主数据变化影响。首次创建会先锁定企业和所选商品，再在同一事务读取并展开完整 SKU 集合；没有 SKU 的商品按 SPU 创建任务项，因此并发新增 SKU 不会落在事务读取与任务写入之间。`batch_production_snapshots` 按任务分别保存一份品牌快照、每个商品快照和每个 SKU 快照，任务项只保存三个快照 ID，避免为每个生产项重复存储整包输入；单任务最多 5000 个生产项，单企业处于 `queued` 或 `running` 的生产项合计最多 10000 个，创建和人工重试均在企业锁内检查上限。去重后的快照总量限制为 16MB，后续主数据修改不会改变已经提交的生产输入。任务项支持 `queued`、`running`、`completed`、`failed`、`cancelled` 状态、不可伪造的 `lease_token`、`lease_expires_at`、尝试次数、结果地址和错误信息。

独立 `batch-worker` 进程通过数据库条件更新原子领取，每 2 分钟续租，并把输入快照、模板、任务项以及快照引用媒体的 30 分钟私有地址发送给 `BATCH_WORKER_EXECUTOR_URL`。领取按企业最近领取游标轮转，再在企业内按创建顺序领取，避免单个大租户长期占满全局 FIFO；候选企业使用索引顺序和相关 `EXISTS` 判断，不再为每个生产项聚合、排序全局队列。领取、续租、取消、完成和超时归档统一先锁企业；`BATCH_WORKER_TENANT_CONCURRENCY` 限制单企业同时运行数量，默认 2 且不会超过 `BATCH_WORKER_CONCURRENCY`。执行器地址、执行器返回地址及结果重定向只允许 HTTPS，携带 Bearer Token 的执行请求完全禁止跟随重定向。执行请求使用“任务项 ID + `run_number`”作为 `Idempotency-Key`，同一轮租约接管保持幂等，人工重试递增轮次后允许真正重跑；执行器必须据此幂等处理，并返回 `resultUrl`、`mimeType` 和 `size`。Worker 在归档前同步确认租约，通过拒绝私网解析、限制重定向和任务 Context 控制的 HTTP 流式读取获取结果，七牛上传凭证同时强制精确大小、媒体类型和对象键，实际读取最多为声明大小加 1 字节；归档文件使用“任务随机 `archive_token` + 任务项 ID + `run_number`”确定的稳定 `storageKey`，`batch-result-` 前缀禁止从用户上传入口创建，进程在文件确认后、任务完成前退出时，租约重投递会复用已校验结果而不是重复占用企业额度。校验成功后结果写入 `organizations/{organizationId}/batch-results/`，在企业额度事务中确认文件，并让任务项保存 `result_storage_key` 和事务型文件引用。任务项只持久化固定安全错误文案，服务日志只记录任务项和错误类型，不保存外部 URL、签名参数、内部地址或上游错误原文。连续 5 次租约超时会自动失败，人工重试会开启新的尝试周期；取消会清空租约并中止仍在进行的结果读取或上传。可通过 Docker Compose `worker` profile 启动，`BATCH_WORKER_TOKEN` 用于执行器鉴权。正式环境应让 API 与 Worker 共用 MySQL 或 PostgreSQL，不使用 SQLite 承载多进程生产队列；租约和业务时间统一保存为固定九位小数的 UTC RFC3339，保证字符串条件比较与时间先后一致。

### users

系统用户表。用户基础信息、角色和算力点余额放在该表中。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 主键 |
| `username` | string | 用户名，唯一索引 |
| `password` | string | 密码哈希 |
| `email` | string | 邮箱 |
| `email_key` | nullable string | 规范化邮箱唯一键；历史空值为 `NULL`，新注册用户用于防止并发重复注册 |
| `display_name` | string | 昵称 |
| `avatar_url` | string | 头像地址 |
| `organization_id` | string | 新会话默认/最近使用的企业 ID，不作为业务请求的唯一租户上下文 |
| `role` | string | 角色：`user`、`admin` |
| `group` | string | 用户计费分组，默认 `default` |
| `credits` | number | 算力点余额 |
| `aff_code` | string | 用户自己的邀请码，唯一索引 |
| `aff_count` | number | 已邀请用户数量，冗余统计字段 |
| `inviter_id` | string | 邀请人用户 ID |
| `github_id` | string | GitHub 用户 ID |
| `linux_do_id` | string | 历史预留字段，当前登录流程不再使用 |
| `wechat_id` | string | 微信用户 ID |
| `status` | string | 用户状态：`active`、`ban` |
| `last_login_at` | string | 最近登录时间 |
| `extra` | json | 扩展信息 |
| `created_at` | string | 创建时间 |
| `updated_at` | string | 更新时间 |

### settings

系统配置表，只保存两行数据：`public` 放前端可读取的公开配置，`private` 放仅后端和管理员可读取的私有配置，配置值都用 JSON。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `key` | string | 主键：`public`、`private` |
| `value` | json | 配置内容 |
| `created_at` | string | 创建时间 |
| `updated_at` | string | 更新时间 |

`public.value` 常放前端展示和可公开读取的配置，例如模型列表、登录开关等。  
`private.value` 常放渠道密钥、登录密钥、后台内部开关等。

当前系统设置接口会按后端结构体序列化和反序列化已知字段；数据库 JSON 中额外存在的旧字段会被忽略。

`public.value` 当前字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `modelChannel` | object | 模型渠道公开配置组 |
| `auth` | object | 公开登录和新用户奖励配置 |
| `announcements` | object | 平台公告开关和公告列表 |
| `checkIn` | object | 每日签到和奖励配置 |

`modelChannel` 当前字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `availableModels` | string[] | 系统可用模型列表 |
| `models` | object[] | 模型中心配置，包含模型名称、类型、支持操作、启用状态、排序、宽高比和分辨率档；渠道新模型会自动补入，图片默认 1K、视频默认 720P |
| `pricingRules` | object[] | 模型算力点配置；新增模型会按模型能力自动生成默认规则 |
| `groupRatios` | object | 用户分组倍率配置 |
| `defaultModel` | string | 默认模型 |
| `defaultImageModel` | string | 默认图片模型 |
| `defaultVideoModel` | string | 默认视频模型 |
| `defaultTextModel` | string | 默认文本模型 |
| `systemPrompt` | string | 系统提示词 |

`pricingRules` 每项字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `model` | string | 模型名称 |
| `operation` | string | 由模型中心 `operations` 自动展开的内部操作类型 |
| `unit` | string | 由模型类型自动生成的内部计费单位 |
| `resolutionTier` | string | 分辨率价格档；为空时是默认价格 |
| `billingMode` | string | 计费模式：`fixed` 固定单价，`ratio` 倍率计费 |
| `credits` | number | 固定计费模式下的基础单价 |
| `modelRatio` | number | 倍率计费模式下的模型倍率 |
| `completionRatio` | number | 补全倍率，预留给后续 token usage 结算 |

`auth` 当前字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `allowRegister` | bool | 是否允许用户注册 |
| `newUserReward` | bool | 是否向新注册用户赠送额度 |
| `newUserRewardCredits` | number | 新用户实际赠送额度 |
| `emailVerification` | bool | 注册强制邮箱验证，固定开启 |
| `emailDomainRestriction` | bool | 是否限制可注册邮箱域名 |
| `emailDomains` | string[] | 允许注册的邮箱域名列表 |

`announcements.items` 每项包含 `id`、`title`、`content`、`type`、`publishAt`、`enabled`；公开接口只返回已启用且到达发布时间的公告。

`checkIn` 当前字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `enabled` | bool | 是否开启每日签到 |
| `reward` | bool | 签到是否赠送额度 |
| `rewardCredits` | number | 每次签到赠送的固定额度 |

`private.value` 当前字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `channels` | object[] | 模型渠道配置列表 |
| `promptSync` | object | GitHub 远程提示词定时同步配置 |
| `email` | object | SMTP 私有配置；密码读取时脱敏，不会出现在公开设置接口 |

`channels` 每项字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `protocol` | string | 协议，当前支持 `openai` |
| `name` | string | 渠道名称 |
| `baseUrl` | string | 渠道接口地址 |
| `apiKey` | string | 渠道密钥 |
| `models` | object[] | 渠道模型映射与能力列表 |
| `weight` | number | 渠道权重，同一请求命中多个能力相符的渠道时按权重随机 |
| `enabled` | bool | 是否启用 |
| `remark` | string | 备注 |

`channels.models` 每项字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `model` | string | 对外模型名，与模型中心和计费规则关联 |
| `upstreamModel` | string | 当前渠道使用的真实上游模型名 |
| `operations` | string[] | 当前渠道支持的操作列表 |
| `resolutionTiers` | string[] | 当前渠道支持的分辨率档列表，图片使用 `1k/2k/4k`，视频使用 `480p/720p/1080p`；无分辨率概念的模型为空 |

`promptSync` 字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `enabled` | bool | 是否开启定时同步，默认开启 |
| `cron` | string | Cron 表达式，默认每 5 分钟 |

后端请求模型时，先按对外模型名、操作和分辨率档筛选启用且能力相符的渠道，再按 `weight` 加权随机选择一个渠道；统一售价仍由公开 `pricingRules` 决定，渠道配置只影响路由和上游模型映射。

### email_verifications

注册邮箱验证码表。每个规范化邮箱只保留最新验证码，主键为邮箱 SHA-256 标识，不保存明文验证码。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 规范化邮箱的 SHA-256 标识，主键 |
| `email` | string | 规范化邮箱，仅用于注册校验和后台排查 |
| `code_hash` | string | 验证码 HMAC-SHA256 摘要 |
| `request_ip` | string | 请求来源 IP，用于发送频率限制 |
| `expires_at` | string | 验证码过期时间 |
| `sent_at` | string | 最近发送时间 |
| `attempts` | number | 验证失败次数，最多 5 次 |
| `used_at` | string | 一次性消费时间，空值表示未使用 |
| `created_at` | string | 首次创建时间 |
| `updated_at` | string | 最近更新时间 |

注册成功时，`used_at` 更新、用户创建、默认企业、所有者成员关系和新用户额度流水写入同一数据库事务；并发请求只有一次可以消费成功。

### check_ins

用户每日签到记录表。`user_id + check_in_date` 是联合唯一索引，防止并发请求重复签到和重复发放额度。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 主键 |
| `user_id` | string | 关联用户 ID |
| `check_in_date` | string | 签到日期，按 Asia/Shanghai 的 `YYYY-MM-DD` 保存 |
| `reward_credits` | number | 本次实际获得的额度，未开启奖励时为 0 |
| `created_at` | string | 创建时间 |

### credit_logs

用户算力点变更流水表。当前记录后台调整、模型消费与返还、兑换码、签到和新用户赠送。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 主键 |
| `user_id` | string | 关联用户 ID |
| `type` | string | 额度变动类型 |
| `amount` | number | 本次变动数量，增加为正，扣减为负 |
| `balance` | number | 变动后的用户算力点余额 |
| `related_id` | string | 关联业务 ID，可为空 |
| `remark` | string | 备注 |
| `extra` | json | 扩展信息 |
| `created_at` | string | 创建时间 |

`type` 当前取值：

| 值 | 说明 |
| --- | --- |

### user_files / user_file_upload_reservations / user_file_upload_rate_limits / user_file_references / user_object_deletions

企业云端媒体文件及其上传、引用和回收状态。文件本体保存在七牛云 Kodo 私有空间，数据库只保存企业鉴权、对象定位和读取所需的元数据。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 主键 |
| `organization_id` | string | 所属企业 ID |
| `user_id` | string | 上传用户 ID |
| `storage_key` | string | 前端媒体存储编号；与 `organization_id` 组成联合唯一索引 |
| `object_key` | string | 七牛云私有空间内的对象键，不通过接口返回 |
| `hash` | string | 七牛云返回的文件内容 ETag |
| `mime_type` | string | 媒体 MIME 类型 |
| `size` | number | 文件字节数 |
| `unreferenced_at` | string | 首次确认没有业务对象引用的时间；重新被引用时清空 |
| `created_at` | string | 创建时间 |
| `updated_at` | string | 更新时间 |

单文件上限为 80MB，`storageKey` 最长 191 字节；企业默认额度由 `USER_STORAGE_QUOTA_MB` 配置，默认 5120MB。申请上传时，后端锁定企业记录，在 `user_file_upload_reservations` 中原子预留新增空间并同时计算其他待上传预留，防止多成员并发突破企业额度。企业最多保存 100000 个正式文件、同时持有 512 个有效上传预留和 10000 个“有效预留 + 待删除对象”，单用户最多同时持有 64 个有效预留和 1000 个临时对象，避免小文件绕过字节额度放大数据库记录。预留的 `cleanup_reserved_bytes` 按“本次对象大小”和“可能被替换的旧对象大小”取较大值；`user_object_deletions` 同时保存企业、用户及对象字节数。有效预留的潜在清理字节与待删除对象字节合计不得超过同一企业额度，从而把仍有效但已取消或被取代的上传凭证也纳入物理临时空间上限。过期预留和正式文件 GC 每次最多处理 500 条，并使用企业、到期时间及无引用时间复合索引。浏览器上传凭证和预留有效期为 20 分钟，覆盖 15 分钟客户端上传上限及确认余量；用户中止或上传失败后会通过鉴权取消接口立即释放逻辑预留。未确认临时对象不会立即删除，而是在凭证过期后再保留 15 分钟在途上传宽限，避免删除任务先收到“对象不存在”、随后上传完成而形成孤儿对象。每次上传都使用 `organizations/{organizationId}/uploads/{uploadId}` 下的唯一临时对象键；相同 `storageKey` 不会跳过本次内容校验，确认时以后端读取的七牛 ETag 和实际大小判定是否复用旧文件，内容不同会清理临时对象并返回编号冲突。只有旧对象确实缺失或权威元数据与数据库不一致时才允许修复替换，预留同时绑定被修复的原对象键，避免并发修复覆盖其他成员刚确认的新文件。有效预留会阻止同一 `storageKey` 的旧文件被 GC；上传凭证按声明媒体大类限制 MIME，确认阶段再次核对对象实际媒体大类与存储编号，避免图片编号挂接视频或音频。HEAD 健康检查同时核对数据库 ETag、七牛 ETag、大小和媒体大类，同大小的错误内容不会被视为健康文件。上传确认还会在企业锁内按当前文件、其他预留和实际大小重新计算额度，避免旧文件回收后差额预留失真。上传完成后由后端读取对象元数据，在同一事务中确认 `user_files`、释放预留并把待清理对象写入删除队列；长期 Access Key 和 Secret Key 只保存在服务端。

`user_file_references` 在画布、素材、生成记录、品牌、SKU、批量输入快照和批量结果保存事务中按业务对象替换 `storage_key` 引用，并在写入前验证文件已确认存在。文件确认、引用替换、上传预留创建、取消和过期都会在同一企业锁事务中即时写入或清空 `unreferenced_at`；后台只按索引扫描已到期记录，不再周期性反查全部正常文件。持续 24 小时无引用后才删除文件记录并写入 `user_object_deletions`。业务请求只提交删除事件，不调用七牛删除；对象删除完全由后台 Worker 使用租约领取、指数退避和幂等“对象不存在即成功”语义执行，避免数据库事务或用户请求等待外部存储，也避免多实例重复处理。浏览器直传具有 15 分钟上限并可由上传组件取消；文件读取必须先通过当前企业成员鉴权，后端再返回 10 分钟有效的私有下载地址，不能跨企业访问。

`user_file_upload_rate_limits` 按企业和用户分别保存当前分钟窗口计数；企业每分钟最多申请 600 个上传凭证，单用户每分钟最多申请 120 个。计数与企业行锁配合，在多 API 实例下保持一致；达到上限后的请求不会继续执行对象状态检查和上传预留事务。

七牛云连接由 `QINIU_ACCESS_KEY`、`QINIU_SECRET_KEY`、`QINIU_BUCKET`、`QINIU_REGION` 和 `QINIU_DOWNLOAD_DOMAIN` 配置；私有下载域名必须是无用户信息的完整 HTTPS URL。
