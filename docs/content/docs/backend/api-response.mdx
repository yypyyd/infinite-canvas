# 接口响应约定

后端业务接口统一返回 JSON：

```json
{
  "code": 0,
  "data": {},
  "msg": "ok"
}
```

- `code`: 业务状态码，`0` 表示成功，非 `0` 表示失败。
- `data`: 业务数据。失败时通常为 `null`。
- `msg`: 响应消息。成功默认为 `ok`，失败时放错误原因。

前端请求逻辑以 `code` 判断业务是否成功。当前后端业务失败也会返回 HTTP 200，前端不要只依赖 HTTP 状态码判断结果。

接口连接失败、服务不可达、返回体不是约定 JSON 时，前端按网络或接口异常处理。

## 管理员协议预览

`POST /api/admin/settings/protocol-preview` 使用管理员鉴权和上述统一响应，接受 `template`、`operation`、`phase`（`create` 或 `resume`）、`variables`、可选字符串 `response`。仅校验模板、渲染示例请求和解析 JSON / NDJSON，不访问上游；`data` 返回 `method/path/headers/body` 及可选 `frames`，鉴权变量始终替换为 `***`。模板持久化仍通过设置接口，详见[自定义渠道协议](./custom-protocols)。

自定义媒体渠道对用户端保持现有 `/api/v1/*` 入参及归一化图片/视频响应，协议模板与渠道地址不对用户公开。提交结果不确定时返回 `submission_pending`，已提交但当前等待结束时返回 `generation_pending`，按原请求编号恢复；不得将其当成可以重新创建任务的信号。

## 工作区增量同步

`POST /api/workspace/sync` 使用登录会话和当前企业鉴权，请求体为 `{ "versions": [{ "domain": "canvas_project", "objectId": "画布ID", "version": 1 }] }`。首次传空数组；服务端只返回当前企业中版本不同或尚未读取的记录，响应仍为 `{ code, data: { records: [...] }, msg }`。删除记录返回 `deleted: true`、新版本号且不带 `data`，无变化返回空数组。前端合并增量，不能把未返回的记录当作删除；已知版本和文件检查结果只保留在当前页面内存。

画布保存仍提交读取时的版本。冲突时保留服务端最新画布并另存本地冲突副本，禁止仅更新旧画布的版本号后重试覆盖；副本成功写入后再提示用户。

## 用户 API Key

面向外部调用方的完整示例按类型分开：[图片对接](/docs/api/image)、[视频对接](/docs/api/video)、[音频对接](/docs/api/audio)。`ic_live_` API Key 调用 `/api/v1/*` 时，成功响应保持各接口自己的结果；失败返回对应 HTTP 状态码和 OpenAI 错误体，不再使用 `{ code, data, msg }`。登录会话调用同一路由时，失败仍是 HTTP 200 的 `{ code, data, msg }`。

```json
{
  "error": {
    "message": "该模型或当前规格未设置价格",
    "type": "invalid_request_error",
    "param": "model",
    "code": "model_not_priced"
  }
}
```

官方 SDK 把 `base_url` 设为 `https://huantu.xyz/api/v1`，视频路径是 `/videos`，不是 `/video`。

登录用户可在当前企业内管理自己的 API Key：

- `GET /api/api-keys`：返回当前用户在当前企业创建的 Key，完整密钥不会返回。
- `POST /api/api-keys`：接受 `{ "name": "生产服务器" }`，完整 `secret` 仅在本次成功响应中返回。
- `DELETE /api/api-keys/:id`：永久删除当前用户在当前企业内的 Key，删除后立即失效且记录不可恢复。

每个用户在每个企业最多有 10 个有效 Key。调用 AI 接口时使用：

```http
Authorization: Bearer ic_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

用户 API Key 只用于同源后端 `/api/v1/*` 路由，继续复用创建用户、绑定企业、后台模型渠道、用户组计价、企业扣费模式、企业额度和生成任务记录；调用方无需传 `X-Organization-ID`。若请求仍传入 `X-Organization-ID` 或 `organization` 查询参数，必须与 Key 绑定企业一致，否则服务端拒绝请求。Key 不能调用 `/api/auth/*`、`/api/admin/*`、`/api/commerce/*`、画布数据、用户资料或 Key 管理接口。

## 邀请返佣

登录用户可通过 `GET /api/referrals` 查看自己的邀请码、已邀请人数、累计返佣、当前返佣开关与比例，以及分页明细。返佣链接使用 `/login?ref=邀请码`，注册请求也可直接提交 `referralCode`；邀请码只在注册成功时绑定一次。

返佣只在被邀请用户的首笔充值成功时按私有设置中的比例计算，基数为该订单实付金额，直接写入邀请人的人民币余额和 `balance_logs`。第二笔及后续充值不再返佣；首笔充值发生时规则关闭、比例为 0 或邀请人失效，也不会把资格顺延到后续订单。支付通知幂等处理，重复通知不会重复增加余额。返佣不修改算力点，也不提供提现接口。

`GET /api/v1/models` 返回当前开放的图片、视频和音频模型，不返回文本模型。响应保持 OpenAI 模型列表的 `{ "object": "list", "data": [...] }` 结构，每项包含标准的 `id`、`object`、`created`、`owned_by`，并补充显示名称、类型、支持操作、宽高比、分辨率档和视频时长；接口使用与生成请求相同的 Bearer 鉴权：

```bash
curl "https://huantu.xyz/api/v1/models" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

图片生成示例：

```bash
curl -X POST "https://huantu.xyz/api/v1/images/generations" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"YOUR_IMAGE_MODEL","prompt":"生成一张商品主图","size":"1024x1024","n":1}'
```

### 安全边界与已知限制

- 威胁模型覆盖数据库泄漏导致明文 Key 暴露、跨企业伪造、已撤销 Key 重放，以及使用 Key 进入账号或管理接口。完整 Key 由 32 字节安全随机值生成，数据库只保存 SHA-256 摘要；摘要适合验证高熵随机凭据，不能恢复原始 Key。
- Key 鉴权会逐请求复核用户状态、企业状态和成员关系。用户封禁、成员移除、企业停用或 Key 撤销后，后续请求立即拒绝。
- 服务访问日志不得记录 Authorization、Cookie、请求体或完整 Key；企业审计日志只记录 Key 编号、名称和可辨认前缀。
- 当前复用账号及企业额度、预算和既有接口防护，暂不提供单 Key 独立额度、细粒度 scope、过期时间或单 Key 限流。商业开放前仍应在反向代理层配置通用速率限制，并在后续版本按套餐增加 Key 级配额和限流。
- 原始 Key 只展示一次，用户遗失后只能撤销并重新创建；前端不得把 Key 写入 localStorage、IndexedDB、日志或分析事件。

## 企业电商生产接口

企业接口继续使用 `X-Organization-ID`，服务端逐请求复核当前用户成员关系。新增真实可用接口包括：

- `POST /api/commerce/production/image/preflight`：规范化商品/SKU 范围与模板选择，返回任务项数、问题定位和提示词预览；服务端创建任务时会重新验证。
- `POST /api/commerce/batch-jobs`：兼容旧单模板请求，同时接受 `productScopes + templateSelections`；`requestId` 同内容重放返回原任务，不同内容返回冲突。
- `GET /api/commerce/batch-jobs/:id`：返回父任务、冻结模板选择与聚合进度；运行中前端可每 5 秒轮询。
- `/api/commerce/video-projects` 及 `/:id/preflight`、`/:id/versions`：保存草稿、执行预检、冻结不可变版本。Release 1 没有 render 接口，不返回视频排队任务或 MP4。

图片父任务可能返回 `pending_review` 和 `partial_success`；前者表示所有执行项完成并等待审核，后者表示成功与失败并存。持久化文件字段仍为 `storageKey`，签名 URL 不进入响应模型或数据库。

## Agent 事件流

`GET /api/v1/agent/runs/:id/events` 使用 SSE 按 `after` 游标补放并推送 Run 事件。Run 进入终态或 `waiting_confirmation` 后服务端会主动结束当前连接，避免在人为等待期间维持长连接；用户提交澄清回答或破坏性操作决定后，前端按最后已处理序号重新连接同一 Run，已保存事件可幂等重放。

提交 Agent 消息时，`canvasContext.autonomy` 取 `cautious`、`standard` 或 `autonomous`。完整上下文最多 10000 个节点、50000 条连线和 16MB，`selectedNodeIds` 最多 10000 个，`focusNodeIds` 最多 20 个，`visibleNodeIds` 最多 40 个；初始 `canvasSnapshot` 最多 16MB，HTTP 请求体最多 32MB。模型上下文仅保留有限节点详情及总数、范围摘要，节点存储键不进入模型 JSON。`canvas.read` 支持 `nodeIds`、`query`、`offset`，从执行页面的当前状态返回最多 20 个匹配节点及相关连线；工具结果中的 `canvasContext` 经服务端规范化，与回执在同一事务内更新 Run 上下文。读取结果由服务端从这份上下文裁剪，澄清回答也会刷新上下文。原始撤销快照保持不变。

自然语言始终由模型通过结构化工具规划；不会根据关键词直接修改画布。每次只执行一个工具，回传结果后再规划；上游忽略 `parallel_tool_calls: false` 时只执行首个调用，再依据真实结果决定下一步。媒体分批生成允许相同参数，其他重复修改会停止并明确提示；读取、澄清和视觉验收不推进业务计划步骤。首次可重试工具失败可重新规划一次，后续失败终止；图片/视频生成后安排视觉验收，验收不可用或未通过不能视为目标完成。

图片/视频工具支持 `configNodeId`、`model`、`size` 等显式设置；图片支持 `quality`，分辨率使用 `size` 像素尺寸，视频支持 `resolution`、`generateAudio`。配置节点可设置生成类型、提示词、数量和时长。执行时读取指定配置和实际入边中的文本/参考媒体；明确工具参数优先，省略提示词使用配置当前完整提示词，用户清空后不会回用历史提示词；省略数量/时长使用配置值，无配置时图片默认一张、视频沿用当前默认时长，产物连接到配置节点。模型不支持指定时长、规格或参考媒体时明确失败，不能丢弃参考或静默替换规格。删除、覆盖文本、保存/遗忘记忆仍需用户确认。

`budget` 固化工具、媒体、时间和算力上限。前三项在下一步与手动重试前检查；每次文本、媒体和视觉验收任务在实际扣费事务内锁定所属 Run，并检查累计未退款算力加本次费用不超过上限，取消或终止后不允许新付费调用；已创建媒体任务按实际结果继续归档结算。15 分钟工具等待回收以最后心跳为依据，持续续租的视频不会仅因 Run 等待时间长而失败。

`GET /api/v1/agent/runs?projectId=...` 返回当前企业、用户和项目的未结束运行及原始请求、引用节点信息。刷新会保持旧对话清空的规则，但恢复未结束任务的控制入口并从持久事件及工具回执续接；删除会话须先取消其运行。执行页面关闭时画布工具暂停，重新进入后可续接；媒体任务归档由现有服务端任务机制负责。

`GET /api/v1/agent/runs/:id/diagnostics` 返回安全运行诊断、计划、预算、实际用量和停止原因，不包含完整 Context、原始输入输出、租约、快照或媒体存储键。`GET /api/v1/agent/metrics?hours=24` 返回当前企业与账号范围的聚合指标。`POST /api/v1/agent/runs/:id/steps/:callId/retry` 只允许预算内的可重试失败步骤创建新调用编号。

整轮撤销使用工作区 `agentToolReceipts` 中每次修改的局部补丁，按逆序恢复受影响的节点字段与连线，保留无关手动改动；内容已被后续改写时整体拒绝撤销，缺失补丁也不会回退覆盖整张画布。客户端先停止运行、校验并保存撤销结果，再向 `POST /api/v1/agent/runs/:id/revert` 提交 `{ callIds: [...] }` 标记已应用工具的撤销状态；保存失败可重试，费用不返还。接口保留原始所有者隔离快照与校验值供审计，客户端不再用它覆盖整张画布。
视觉验收的信任边界仍在同源服务端：`image.inspect.nodeIds` 必须属于本轮固化画布或本轮已成功生成的图片节点，最多四个且不可重复；`video.inspect.nodeId` 必须属于同一授权范围内的视频节点。浏览器只把工作区预览图或本地抽取的六张视频关键帧转成内联图片提交到 `/api/v1/chat/completions`，不会把渠道 Base URL、API Key 或签名 URL 交给模型。视频验收只依据关键帧可见内容判断主体一致性、构图、明显画面缺陷、镜头稳定性和连续性，不判断声音或关键帧无法证明的完整运动。验收响应使用固定字段白名单和长度限制严格解析，格式异常降级为 `unavailable`；服务端再次校验状态、问题列表和修订提示词的组合，不能借验收结果绕过节点授权或破坏性确认。

## Agent 长期记忆

画布 Agent 的长期记忆保存在服务端，不提供浏览器持久化副本。模型工具的记忆写入与回执提交处于同一事务，须先验证用户确认、运行状态和未过期执行租约；拒绝请求和回执重放不能改动记忆。模型在用户明确表达长期偏好、项目事实或约束时提出 `agent.remember`，批准后才写入；`agent.forget` 同样需要确认。运行结束后可向 `POST /api/v1/agent/runs/{id}/feedback` 提交 `accepted`、`helpful`、`unhelpful`、`deleted` 或 `corrected`。反馈只低幅调整该 Run 产生的 `experience` 记忆，且同一 Run 以最新反馈为准；画布手动删除 Agent 产物和改写 Agent 文本会自动提交对应信号。低于置信度门槛、过期或 `forgotten` 的记忆不会注入后续 Run。

用户也可在 Agent 设置中直接管理记忆：`GET /api/v1/agent/memories?projectId=...&page=1` 每页返回 20 条本画布及账户的 active 记忆，响应为 `{ items, total }`；`POST /api/v1/agent/memories/:id` 接收 `{ content }` 修改文字，或 `{ forget: true }` 遗忘。全部操作校验当前企业与账号，文字长度为 1–1000 字；过期和低置信度记忆可在管理入口查看，但不注入模型。
## 请求 ID 与访问日志

- 每个响应都会返回 `X-Request-ID`。客户端可传入由字母、数字、点、下划线、冒号或短横线组成且不超过 128 位的请求 ID；缺失或格式无效时由服务端生成 UUID。
- 同一个请求 ID 会写入结构化访问日志，并在用户端 AI 代理请求中传给上游，便于关联浏览器、API 和上游调用。
- 访问日志使用 JSON，包含 `request_id`、方法、路由模板、HTTP 状态、耗时、响应字节数和客户端 IP，不记录请求体、Cookie、API Key 或签名 URL。
- 批量生产、邀请邮件 Outbox、对象删除、文件维护和提示词同步等后台任务也使用 JSON 日志，统一包含 `component=worker`、`worker` 和 `event`，并按任务类型附带企业、任务、生产项、Outbox 或删除记录编号、尝试次数与耗时。
- Worker 错误只记录 `error_type` 和安全的业务关联字段，不记录 SMTP、对象存储、执行器或远程同步返回的原始错误文本，也不记录收件地址、对象键、访问令牌或签名 URL。

## 健康检查

- `GET /api/health/live` 是进程存活检查，不访问任何依赖。
- `GET /api/health` 与 `GET /api/health/ready` 是就绪检查：并发 ping 幻图数据库，以及内置账号池运行时它的 PostgreSQL 与 Redis（未配置 Redis 时为 `disabled`，不检查；只做 ping，无查询）。全部可用时返回 HTTP 200；任一失败或超过 2 秒时返回 HTTP 503。这是业务接口统一 HTTP 200 规则的明确例外。
- 响应只包含 `ok` / `unavailable` 状态（账号池运行时多一个 `pool: {status, database, redis}`），不含错误详情、地址或 DSN；失败原因只写入服务端日志。Docker 健康检查使用 `/api/health`，依赖不可用时容器会被标记为 unhealthy。
- `GET /api/admin/operations/health` 仅管理员可访问，返回批量生产队列、邀请邮件 Outbox 和对象删除 Outbox 的等待数、失败数及过期租约数，并返回最近 24 小时生成任务的总数、运行中/成功/失败数、终态成功率、平均耗时和 P95 耗时。
- 管理员可在“系统设置 → 运维告警”配置各类积压、失败和过期租约阈值。阈值达到时响应中的 `alerts` 返回 `key`、当前值和阈值，整体状态为 `degraded`；单项阈值设为 `0` 时不告警。
- 队列积压和运维告警不会直接让 readiness 失败，避免探针重启进一步放大积压；外部告警系统应读取管理员健康摘要中的 `status` 与 `alerts`。
