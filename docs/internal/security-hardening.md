# 安全加固部署与验收

本目录不由文档站内容集合、搜索、LLM 导出或 Docker 构建收录。它是仓库维护记录，不是访问控制：公开仓库中的文件仍可被读取，不得放入凭据或未脱敏的测试数据。

## 部署前配置

已提供 `Production security configuration` 手动工作流：`inspect` 只读检查，`configure` 从 GitHub `production` 环境 Secrets 读取 Turnstile 两项配置，写入现有服务器 `.env`，自动生成并复用代理密钥，更新已确认的宝塔 Nginx 应用代理文件；`verify` 检查带指定请求 ID 的来源 IP 探针日志。域名固定为主站和现有内嵌入口。重复执行不会轮换已有代理密钥。

配置工作流使用固定版本的 crossplane 解析 Nginx，并从 Cloudflare 官方地址读取可信网段。只更新通往应用端口的 location；写入后通过 Nginx 检查才平滑重载，失败恢复本次修改前的配置。密钥和输入文件不会进入日志；临时输入在流程退出时删除，不创建生产业务数据备份。

- 在 Cloudflare 创建 Turnstile widget，允许实际使用的登录域名。服务端设置 `TURNSTILE_SITE_KEY`、`TURNSTILE_SECRET_KEY`、`TURNSTILE_HOSTNAMES`（逗号分隔的域名，不带协议或路径）。浏览器只取得 site key；secret 只在服务端。未配置、验证服务不可用、token 重复/过期、hostname/action 不匹配均不签发后台会话。Turnstile 是防自动化校验，不是双因素认证。
- 生成至少 32 字符的随机 `REVERSE_PROXY_TOKEN`，由入口 Nginx、Next 与 Go 共同使用。它必须通过私有部署配置提供，不进入 Git、前端环境变量、响应或访问日志。
- 入口代理必须覆盖客户端的 `X-Real-IP`、`X-Proxy-Token` 和 `X-Forwarded-Proto`。Next 只接受通过密钥校验的地址，再剥离其余来源 IP 头。Go 使用同一校验规则；密钥缺失或不匹配时仅使用 TCP 对端，绝不回退到客户端传入的 XFF。此时代理后的请求会共享 IP 限流桶，必须在开放流量前完成真实 IP 验收。
- 公网只能访问入口代理；保持生产端口绑定 `127.0.0.1:3050:3000`，不要公开 Go 或 Next 的直连端口。

Nginx 对应站点的代理 location 中加入以下配置，替换占位符，并保留已有媒体缓冲等业务设置：

```nginx
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Proxy-Token "替换为与应用环境变量一致的随机密钥";
proxy_set_header X-Forwarded-Proto $scheme;
```

若使用 Cloudflare，应先在 Nginx 中仅信任 Cloudflare 官方网段，再通过 `real_ip_header CF-Connecting-IP` 恢复 `$remote_addr`。不要设置 `set_real_ip_from 0.0.0.0/0`，也不要直接把任意传入的 `CF-Connecting-IP` 复制为真实 IP。可信网段需随官方变更维护；直连入口的请求应继续使用实际 TCP 来源地址。

新配置未部署前，本次代码修改不能被记为线上防护已生效。服务端用户模型新增会话版本字段，旧的无版本令牌不再有效，部署后用户需重新登录。

自动部署在停止当前容器前检查上述四项环境变量及代理密钥长度；缺失时终止部署并保留旧服务。GitHub Actions 同时执行本次新增的认证安全回归测试。此检查不能代替真实入口代理请求头的验收。

## 当前实现边界

- 两个登录端点共用 IP 和账号失败计数；已存在账号按用户 ID 归并，用户名/邮箱不可分别绕过。每维度最多 5 个失败或在途验证，第 5 次失败后锁定 15 分钟，连续触发退避到 30、60 分钟；成功重置账号桶，不清除 IP 的其他失败。返回 429 和实际 Retry-After。
- 限流使用单 API 进程内存，限制 10000 个桶并清理 24 小时未活跃项，重启会清空。当前生产只有一个 API 进程；扩为多副本前必须改为共享限流存储，并配置入口 WAF 的独立保护。没有把未部署的 WAF/告警写成已完成。
- 登录日志事件为 `auth_login`，包含账号标识摘要、来源 IP、request ID、后台标记、结果与状态码，不包含口令、挑战 token 或 JWT。告警系统可对失败与 429 聚合；实际接入仍需运维配置。
- 后台必须通过 `/api/admin/login` 完成人机校验；普通登录端点不能为管理员签发会话。独立后台 Cookie 为 HttpOnly、SameSite=Strict、Path=/api，JWT 最长 12 小时；后台 API 另验 admin scope 和当前数据库角色。普通 Cookie 的有效期沿用现有设置。
- 登出会吊销请求携带的有效会话所对应账号的全部 JWT 会话；改密、后台重置密码、角色/封禁状态变化同样递增会话版本。用户 API Key 是单独的凭据，遵循现有撤销和账号状态校验规则。
- 新设密码至少 12 字符、最多 72 字节，拒绝常见弱口令和单字符重复；不强迫修改已有密码，但新注册、改密、后台设密和初始化管理员采用同一规则。
- 安全响应头禁止后台及后台登录页嵌入；普通页面仅允许自身与既有 New API 来源嵌入。基础 CSP 只限制祖先、base 和 object，不声称已通过完整脚本级 CSP 或全站 XSS 验收。HSTS 仅生产启用，不自动扩大到所有子域。
- `RELEASE_NOTES.md` 是站内版本接口、前端内嵌版本数据、文档更新日志页的唯一发布说明来源；`CHANGELOG.md` 是维护记录。发版需同时维护公开摘要，不再把内部变更全文送入前端。

## 待验收

1. 完成上述配置后，普通与后台各成功登录一次；后台不带挑战、重用挑战、错误 action/hostname 均不得登录，普通端点不得绕过后台验证。
2. 用自有测试账号连续失败 5 次，第 6 次应为 429；轮换用户名/邮箱、两个登录端点以及伪造 XFF/CF/真实 IP 头不能绕过。并发 6 次验证也不能全部通过限额检查。
3. 到期后重新失败，验证 15/30/60 分钟退避；确认成功登录不会清除该 IP 其他账号的失败记录。
4. 匿名后台 API 返回 401；有效普通用户 Bearer 调后台返回 403。前端仍显示后端中文错误；验证码发送限流返回 429。
5. 改密、登出、后台重置密码、封禁后，原令牌访问受保护接口应为 401；解封不能复活旧令牌；旧令牌访问 `/api/auth/me` 为游客。检查并发资料保存不会恢复旧密码或回退会话版本。
6. 不存在用户名与错误密码都执行 bcrypt；无效邮箱验证码搭配不同用户名不能探测是否存在。注册、改密和后台设置短密码或常见弱密码均失败。
7. 后台与后台登录页不能被 iframe 加载；New API 内嵌画布仍可登录、刷新、保存与加载媒体。检查应用及入口代理没有冲突的 CSP/X-Frame-Options。
8. 对真实公网客户端与伪造来源头分别检查 `auth_login`/`http_request`，来源地址应一致、不可伪造；确认告警规则能聚合失败与 429。
9. 文档页面、搜索、LLM 导出不包含内部报告全文；发布接口和前端包只含公开版本摘要。

来源 IP 伪造、并发限流/退避和 JWT 算法/后台有效期回归测试已在 `cd2d0c1` 的 CI 中通过。补齐配置后自动部署成功，API 与两个 Worker 健康；两个线上域名的伪造来源头没有被应用采信，后台与画布响应头符合各自嵌入规则。用户已通过真人验证并登录后台，生成任务管理数据正常加载；匿名后台请求返回 401，公开更新接口仅含摘要。其余边界场景继续按清单验收。本地未执行构建。实现完成即进入 pending-test，用户确认通过后再更新正式功能说明。
