# 视频对接

视频是异步任务。路径是 `POST /videos`，不是 `/video`，也不是 `/videos/generations`。站内说明在 [/api-docs/integration/video](/api-docs/integration/video)，可复制请求在[模型广场](/api-docs)。

| 步骤 | 接口 | 成功时看什么 |
| --- | --- | --- |
| 创建 | `POST /videos` | 顶层 `id` |
| 查询 | `GET /videos/{id}?model=模型ID` | `status`，必须带创建时的模型 ID |
| 下载 | `GET /videos/{id}/content?model=模型ID` | MP4。`Content-Type` 若是 JSON，就是失败 |

每 2–3 秒查一次，只有 `completed` 才能下载。任务号是 `id`。HTTP 状态码大于等于 400 就停，读 `error.message`。`seconds` 和 `size` 以模型广场里该模型的能力为准。

还没拿到 `id` 时，用原 `Idempotency-Key` 调用 `GET /generation-tasks/recovery`。

## Kling 4.0 关键帧与参考图

`kling-4.0` 使用两个独立字段，同一次请求可同时传入，合计最多 10 张图片：

| 参数 | 图片用途 |
| --- | --- |
| `input_reference` | 人物、商品、场景等素材参考；可在提示词里用 `@image1`、`@image2` 引用该字段中对应的图片 |
| `keyframes` | 按上传顺序作为关键帧；第一张是首帧，最后一张是尾帧，中间为连续关键帧；只有一张时是首帧 |

两类图片分别编号，超过合计上限拒绝请求。当前渠道开放 720p、4–8 秒、16:9 / 1:1 / 9:16；参考视频与音频没有在此次变更中开放。`GET /models` 的 `max_reference_images` 为 `10`，`reference_mode: mixed` 表示支持这两类图片。创建任务无需选择图片用途。

```bash
curl "https://huantu.xyz/api/v1/videos" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Idempotency-Key: kling-multi-reference-001" \
  -F "model=kling-4.0" \
  -F "prompt=参考 @image1 中的商品和 @image2 中的场景，缓慢推进镜头" \
  -F "seconds=4" \
  -F "size=1280x720" \
  -F "keyframes=@start.png" \
  -F "keyframes=@end.png" \
  -F "input_reference=@product.png" \
  -F "input_reference=@scene.png"
```

JSON 请求的 `input_reference` 与 `keyframes` 均为数组，每项为图片 base64 或 data URI。站内已上传素材可分别传 `input_reference_storage_keys` 与 `keyframe_storage_keys`，服务端检查文件所属用户后转发；不可混用存储键和原始图片输入。修改图片分类或顺序属于不同请求，使用新的 `Idempotency-Key`。

同一请求的 JSON 参数示例（将占位内容替换成完整的图片 base64）：

```json
{
  "model": "kling-4.0",
  "prompt": "参考 @image1 中的商品，按照关键帧控制起止画面",
  "seconds": "4",
  "size": "1280x720",
  "keyframes": ["data:image/png;base64,START_IMAGE_BASE64", "data:image/png;base64,END_IMAGE_BASE64"],
  "input_reference": ["data:image/png;base64,PRODUCT_IMAGE_BASE64"]
}
```

`@image1` 指向 `input_reference` 的第一张图片，关键帧不占用参考图编号。当前视频页与画布使用 multipart 分别提交两类图片；模型广场的「复制示例」提供相同字段。

只使用统一图片数组的调用方也可传 `reference_mode=asset|frame`；`frame` 不能与独立的 `keyframes` 同时设置。
