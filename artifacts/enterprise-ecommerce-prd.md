# 道生画境企业级电商生成平台增量 PRD

- **文档状态**：Draft / 供架构与研发拆解
- **项目名称**：`infinite_canvas_enterprise_commerce`
- **需求类型**：现有项目增量改造，不推倒重建
- **主要语言**：中文
- **现有技术基线**：Next.js 16 + React 19 + TypeScript + Tailwind CSS + Ant Design + TanStack Query + Zustand；Go + Gin + GORM；SQLite / MySQL / PostgreSQL；Docker
- **目标终端**：桌面 Web 优先，建议基准视口 1440×900，最低支持宽度 1280px
- **产品负责人**：许清楚

## 1. 原始需求复述

将现有 `infinite-canvas` 增量改造成简洁、专业的企业级电商内容生产平台，核心聚焦：

1. **商品图片生成**：围绕商品与 SKU，支持多模板一次选择、批量生成主图、详情图、轮播图等成套素材。
2. **商品视频生成**：支持素材自动拼接、片段转场、字幕、背景音乐，形成可预览和导出的营销视频。
3. **企业后台**：包含商品管理、模板管理、生成任务队列与结果预览、批量操作。
4. **平台能力**：考虑高并发生成任务调度、缓存、统一文件存储、批量导出和失败恢复。
5. **设计方向**：桌面端优先，视觉克制、信息清晰、操作高效，符合企业后台工作流。

## 2. 现状与改造边界

### 2.1 已有能力（应复用）

根据 README、功能文档与关键代码，当前项目不是空白原型，已经具备较完整的生成和企业化基础：

- **创作入口**：商品图生成页、营销视频页、商品画布、提示词/素材库。
- **图片链路**：文生图、图生图/参考图编辑、多张结果、历史记录、下载、存入素材、画布回填；已有商品白底主图、场景图、详情图、促销图、服饰模特图、SKU 系列图预设。
- **视频链路**：文本及图片/视频/音频参考素材、模型参数、异步生成、轮询、停止、下载和归档；但当前主要是“调用模型生成单条视频”，不是营销视频编排器。
- **商品域**：企业、成员与角色，品牌规范，商品/SPU、SKU、SKU 参考图。
- **批量生产**：生产模板及版本、交付规格、商品/SKU 展开、批量任务、任务项、进度、取消、失败重试、审核、主图选择、对比与压缩包下载。
- **任务基础**：独立 Batch Worker、领取/续租/回写机制、单企业并发约束、幂等请求与失败恢复设计。
- **企业能力**：多租户隔离、企业切换、成员邀请、角色权限、审计日志、企业共享额度。
- **文件能力**：企业私有媒体、服务端文件引用、统一归档与下载方向；支持七牛 Kodo 配置。
- **系统后台**：用户、生成任务、算力、渠道、模型、素材、提示词、系统设置和运维巡检。

### 2.2 当前主要问题

1. **业务入口分散**：图片、视频、商品、模板、批量任务分别存在，但“从商品到成套素材”的主路径不够集中。
2. **企业中心过载**：当前 `/commerce` 同页承载企业、成员、品牌、商品、SKU、模板、批量任务、审计等大量 Tab 和弹窗，不利于高频生产操作和深链接定位。
3. **图片批量维度不足**：现有批量任务核心上偏向“单模板 + 单交付规格 + 多商品/SKU”；目标需要“多商品/SKU × 多模板/素材位 × 可选变体数”的一次提交。
4. **模板产品模型偏提示词**：已有企业模板和版本，但尚不足以清晰表达主图、详情模块、轮播位、平台、画幅、数量、必需素材、命名规则等电商交付语义。
5. **视频缺少后期编排**：尚未形成镜头列表、自动拼接、转场、字幕轨、背景音乐与成片导出的完整流程。
6. **任务视图割裂**：系统生成任务与企业批量生产任务在用户认知上不是一个统一队列，用户难以集中查看图片包、视频工程及其子任务。
7. **已实现能力仍有待验收项**：文档明确提示多租户、企业媒体、批量 Worker、备份恢复、真实上游和多数据库等存在发布阻断级验收工作；本次改造不能把“已有代码”直接等同于“生产可用”。
8. **视觉层级需继续企业化**：外围页面虽已有 Apple Store 式改造方向，但商品生产页仍需强化高密度列表、筛选、固定操作区和一致反馈。

### 2.3 增量改造原则

- **保留**：现有账号、企业、多租户、品牌/商品/SKU、画布、素材、模型渠道、生成 API、计费、存储、批量 Worker 与后台能力。
- **扩展**：商品生产工作流、模板元数据、多模板批量任务、视频编排工程、任务聚合视图、结果审核与导出。
- **重组**：将 `/commerce` 的高频业务能力拆成清晰的一级/二级页面；系统管理员后台仍保留，不与企业业务工作台混为一谈。
- **兼容**：现有单次图片/视频创作入口、画布项目和旧生产任务仍可访问；旧模板按“通用图片模板”兼容展示。
- **不要求本期推翻技术栈或生成协议**，具体服务拆分、队列选型和存储实现由架构阶段决定。

### 2.4 本期非目标

- 不建设消费者侧商城、店铺装修、购物车、订单、支付、库存、物流、售后。
- 不直接发布商品到淘宝、京东、抖音、小红书等外部平台；本期只按渠道规格生成与导出。
- 不训练自有基础模型，不建设模型微调平台。
- 不替代 Premiere / 剪映等专业非线性编辑器；视频能力聚焦模板化快速成片。
- 不以手机端完整生产为目标；移动端只保证查看任务、预览结果和基础审核不崩溃。
- 不在本期建设复杂 BI、投放归因或素材转化率闭环。

## 3. 产品目标与成功指标

### 3.1 产品目标

1. **提高成套素材产能**：让运营可从商品/SKU 出发，一次配置并生成多个电商图片位及营销视频，减少重复录入。
2. **建立可控生产流水线**：任务可排队、可追踪、可取消、可重试、可审核、可批量导出，并在多人/多企业场景下严格隔离。
3. **沉淀企业资产与规范**：复用商品资料、品牌规范、模板版本与历史结果，让输出更一致、可复现、可审计。

### 3.2 建议成功指标（上线后 30 天观测）

- 80% 以上的成套图片生产任务可在一次提交内完成，不需要逐模板重复创建。
- 创建“1 个商品 × 3 个图片模板”的人工配置时间不超过 3 分钟（不含模型生成时间）。
- 任务创建幂等：相同请求重复提交不产生重复任务，重复扣费事件为 0。
- 已接受任务的最终状态可追踪率 100%；无永久停留在未知状态的任务。
- 非上游内容失败导致的任务项成功率不低于 99%；失败项可单独重试。
- 跨企业商品、模板、任务、文件泄漏事件为 0。
- 已完成且文件有效的结果导出成功率不低于 99%。
- 桌面端核心页面常规查询 P95 响应建议小于 1 秒（不含生成与文件下载），筛选或翻页后 300ms 内出现加载反馈。

| 企业所有者 Owner | 企业治理与预算 | 全部企业业务权限；成员、角色、所有权、额度与预算、模板发布、审核与导出 |

## 5. 核心用户故事

1. **作为电商运营**，我希望选择一个商品的多个 SKU 和“主图、轮播图、详情图”模板一次生成，以便快速获得一整套上架素材。
2. **作为设计成员**，我希望在提交前预览每个模板将使用的商品资料、参考图、提示词和画幅，以便提前修正错误输入。
3. **作为视频运营**，我希望选择商品图片/视频片段、成片模板和文案后自动生成镜头顺序、转场、字幕和背景音乐，以便快速制作营销短视频。
4. **作为审核人**，我希望按商品/SKU 查看候选结果、参考图和品牌规范，并批量通过、驳回或设为主图，以便保障视觉一致性。
5. **作为管理员**，我希望创建、复制、启停和发布有版本的企业模板，以便团队重复使用且历史任务不受模板更新影响。
6. **作为运营负责人**，我希望统一查看图片包和视频成片任务的排队、运行、成功、失败及成本，以便掌握交付进度并处理异常。
7. **作为企业所有者**，我希望任务与结果严格按企业隔离且有审计记录，以便多人协作时保障数据与预算安全。
8. **作为平台管理员**，我希望看到队列积压、失败率、处理耗时和 Worker 状态，以便高并发时及时扩容或定位故障。

## 7. 关键对象与产品规则

### 7.1 商品与素材

- 商品以 **SPU** 为业务主体，包含品牌、编码、名称、类目、描述、卖点、目标人群、状态。
- SKU 包含编码、名称、属性和参考图；继续沿用现有每 SKU 最多 50 张参考图约束。
- 一次生产必须固化商品、SKU、品牌规范和参考素材快照，后续编辑商品不能改变历史任务的生成输入与审核上下文。

### 7.2 图片模板

图片模板至少具有：

- 模板名称、说明、类型：主图 / 轮播图 / 详情图 / 场景图 / 促销图 / SKU 系列图 / 自定义。
- 适用平台、目标宽高、格式、质量、默认生成数量。
- 提示词及可替换变量；品牌语气、品牌规范、禁用词、商品卖点、SKU 属性可注入。
- 必需参考素材规则、是否需要透明/白色背景、是否预留文案区。
- 状态、当前版本、创建人、更新时间。

**规则**：任务必须引用明确模板版本；模板发布新版本后不影响已创建任务。现有只有 Prompt 的企业模板自动兼容为“自定义图片模板”。

### 7.3 视频模板 / 视频工程

视频模板至少具有：

- 成片比例与分辨率、目标时长、镜头槽位及每镜头建议时长。
- 片段来源规则：商品图、已生成图片、上传视频、AI 生成视频。
- 默认转场、字幕样式、安全区、片头/片尾、品牌 Logo 位。
- 背景音乐来源、音量、淡入淡出；旁白/原声与 BGM 的混音规则。
- 输出格式与文件命名规则。

视频工程保存“素材编排与配置”；视频任务是某个工程版本的渲染执行。修改工程后重新生成应创建新任务/新版本，不能覆盖已交付成片。

### 7.4 任务层级

- **生产任务 Job**：用户一次提交产生的业务任务，可为图片包或视频成片。
- **任务项 Item**：可独立执行、计费、失败、重试和审核的最小单位。
- 图片包任务项默认按 `SKU × 模板 × 变体序号` 展开。
- 视频任务项可按“素材生成子项”和“最终合成子项”展示依赖关系；只有必需子项成功后才能合成。
- 状态统一展示为：草稿、排队中、运行中、待审核、部分成功、已完成、失败、已取消。
- 用户取消后不再领取新任务项；已成功结果保留，运行中项按执行能力尽力停止。

## 8. 需求池

优先级定义：**P0 Must have** 为企业电商生产闭环；**P1 Should have** 为显著提升效率与治理；**P2 Nice to have** 为体验和增长增强。

### 8.1 P0 — Must have

#### A. 商品中心

- 必须提供商品列表独立页面，支持关键词、品牌、类目、状态筛选和分页。
- 必须支持商品新增、编辑、删除/停用，以及 SKU 新增、编辑、状态维护和参考图管理。
- 必须支持列表勾选与批量操作：批量启用/停用、批量加入图片生产；删除需二次确认并报告逐项结果。
- 必须明确显示商品编码、品牌、SKU 数、状态、更新时间和最近生产状态。
- 必须沿用企业隔离、角色权限、乐观版本控制和审计日志。

#### B. 多模板批量图片生产

- 必须支持一次选择 1–200 个商品；任务展开后总生产项不得超过现有 5000 项限制。
- 必须支持一次选择多个图片模板，至少覆盖主图、详情图、轮播图三类；同时可继续使用现有场景、促销、模特、SKU 系列预设。
- 必须支持选择全部 SKU 或指定 SKU，并展示预计任务项数量。
- 必须支持为每个模板配置结果数量、交付规格和必要参数；超出模型能力时提交前阻止并说明原因。
- 必须提供“生成输入预检”：缺少参考图、商品卖点、品牌规范或必填字段时定位到具体商品/SKU/模板。
- 必须在提交前预览至少一个 SKU 在各模板下的最终提示词、参考图和交付规格。
- 必须显示预计算力消耗；余额/预算不足时不得创建部分任务或重复扣费。
- 必须使用幂等请求防止双击或网络重试创建重复任务。

#### C. 模板中心

- 必须分开展示内置模板与企业模板，并支持按图片类型、平台、状态搜索筛选。
- Owner/Admin 必须可创建、复制、编辑、启停和发布图片模板新版本；Member/Reviewer 只读。
- 模板必须包含类型、画幅/交付规格、默认数量、提示词、变量说明和素材要求。
- 必须提供模板预览与提示词变量校验；无效变量不得发布。
- 已被历史任务使用的版本必须可查看且不可被覆盖或物理删除。

#### D. 视频自动成片

- 必须支持从商品/SKU、企业素材和本地上传选择图片/视频片段。
- 必须提供镜头列表，可拖拽排序、删除、替换，支持“一键自动排序/编排”。
- 必须支持自动拼接并至少提供：无转场、淡入淡出、交叉溶解三类转场。
- 必须支持字幕：手动输入/粘贴文案，按镜头自动分段，编辑字幕文本、入出点和基础样式；字幕需有画面安全区预览。
- 必须支持背景音乐：从企业音频素材或本地上传选择，配置音量、循环/裁切、淡入淡出；没有合法音乐时可选择无 BGM。
- 必须支持成片比例 16:9、9:16、1:1，默认导出 MP4；默认建议 1080p，实际可用规格受模板和渲染能力约束。
- 必须提供提交前预览：镜头顺序、总时长、字幕与音乐配置；最终渲染作为异步任务进入任务中心。
- 必须支持失败重试、取消、成片预览和下载；重新编辑后生成新版本，不覆盖旧成片。

#### E. 统一任务中心与结果审核

- 必须聚合图片包与视频成片业务任务，以任务类型、状态、创建人、商品、时间筛选。
- 必须展示父任务进度、成功/失败/排队项数、创建人、预计/实际消耗、创建和完成时间。
- 必须提供任务详情：输入快照、模板版本、子项列表、实时/轮询进度、错误摘要、结果缩略图/播放器。
- 必须支持取消整单、重试失败项；成功项不得因失败项重试而重复执行或重复计费。
- 必须支持结果审核：Owner/Admin/Reviewer 可通过或驳回，驳回必填原因；图片候选可设为主图。
- 必须支持 2–4 张图片并排对比，显示参考图、商品/SKU 快照和品牌规范。
- 必须支持列表勾选后的批量通过、批量驳回、批量重试和批量导出；无权限或状态不匹配项必须跳过并给出清单。

#### F. 统一存储与导出

- 生成结果必须归档到企业私有文件存储并以服务端文件引用持久化，不能依赖浏览器 Blob 或上游临时 URL 作为最终交付。
- 图片、视频、音频、字幕/工程配置必须按企业隔离；签名地址过期后可重新获取。
- 必须支持单文件下载和任务级打包导出；图片包按商品编码/SKU/模板类型命名并避免同名覆盖。
- 批量导出只包含有权限且文件有效的结果；缺失文件、超限或没有可导出项时必须明确失败原因。
- 必须保留现有“通过结果导入企业素材或画布”的能力。

#### G. 高并发任务产品要求

- 必须沿用异步队列与独立 Worker 处理长任务；API 接收任务后不得阻塞等待整个生成/渲染完成。
- 必须保证任务项不被多个 Worker 重复执行；租约过期可安全接管，旧执行者不得覆盖新结果。
- 必须保持跨企业公平性，单企业不能长期占满全部执行槽。
- 必须支持按企业、任务类型或模型能力设置并发/排队上限；超限时明确显示“排队中”而非通用失败。
- 必须具备任务幂等、失败退避、有限自动重试、人工重试和失败终态。
- 平台管理员必须能看到队列积压量、运行数、失败数、平均/P95 耗时、Worker 最近心跳/租约异常。

#### H. 缓存与一致性产品要求

- 商品、模板、任务列表可缓存以提升读取效率，但企业切换或实体更新后必须失效，不得跨企业复用数据。
- 相同文件缩略图与元信息可复用；原始结果仍以统一存储为准。
- 任务状态在运行期间建议 5 秒内刷新，完成后停止高频轮询；用户手动刷新必须立即查询服务端状态。
- 浏览器不得持久化 API Key、企业私有文件或完整业务数据库副本；断网时明确提示未保存。

#### I. 桌面端企业级 UI

- 必须采用固定顶部栏 + 可折叠左侧导航 + 主内容区，列表页操作条和筛选区位置一致。
- 必须统一表格密度、圆角、状态色、空状态、加载态、错误态和二次确认。
- 主要操作按钮只有一个视觉主行动；危险操作使用红色且不与普通操作并列混淆。
- 1280px 宽度下核心表格不得遮挡创建、筛选、分页和批量操作；宽表可横向滚动并固定关键列。
- 必须保留浅色/深色主题的可读性；键盘焦点清晰，常用点击目标不小于 36px，重要触控目标建议 44px。

## 9. 关键业务流程

### 9.1 多模板批量图片生产

1. 用户从商品列表勾选商品并点击“批量生成图片”，或从图片生产页选择商品。
2. 选择 SKU 范围；系统展示 SKU 数与缺少参考图等问题。
3. 选择多个模板（如主图、轮播图、详情图），设置每模板数量与交付规格。
4. 系统计算 `SKU × 模板 × 数量` 的任务项总数和预计消耗；超过 5000 项时阻止提交并引导拆单。
5. 用户选择一个 SKU 预览各模板的最终提示词、参考图、品牌规范和画幅。
6. 提交后固化商品、SKU、品牌、模板版本和交付规格快照，生成唯一父任务。
7. Worker 按公平调度处理任务项；页面展示排队/运行/成功/失败进度。
8. 用户进入结果页对比、通过/驳回、选择主图；仅重试失败/驳回项。
9. 用户将通过结果存入素材/画布，或按商品/SKU/模板目录打包导出。

### 9.2 视频自动成片

1. 用户选择商品/SKU 与视频模板，或新建空白视频工程。
2. 系统加载 SKU 参考图、已生成图片/视频和企业素材；用户补充上传素材。
3. 系统按模板自动形成镜头建议，用户调整顺序、时长、裁切策略和转场。
4. 用户输入营销文案，系统按镜头分段生成字幕草稿；用户编辑文本与时间。
5. 用户选择 BGM，调整音量、裁切、循环和淡入淡出；预览总时长和声音关系。
6. 预检素材缺失、时长、比例、字幕越界和音乐版权确认。
7. 提交异步渲染任务；如部分镜头需 AI 生成，先完成依赖子项，再执行最终合成。
8. 完成后在线播放、审核、下载或保存到企业素材；修改工程再次提交时生成新版本。

### 9.3 任务异常与重试

1. 系统区分可重试错误（限流、临时网络、Worker 中断）与不可重试错误（参数非法、素材缺失、内容违规）。
2. 可重试错误按有限次数和退避规则自动重试，页面显示尝试次数；不可重试错误直接进入失败并给出可行动提示。
3. 父任务可呈现“部分成功”；成功结果不回滚，失败项可人工重试进入新轮次。
4. 重复回调、重复点击和请求重放不得重复写结果或扣费；失败退款只执行一次。

### 9.4 批量审核与导出

1. 审核人按任务/商品/SKU/模板筛选待审核结果。
2. 可 2–4 项对比，并查看历史输入快照与自动质量检查。
3. 批量通过前系统只选择满足状态与质量门槛的项；批量驳回必须输入公共原因，可再逐项修改。
4. 导出前校验权限、文件有效性、审核状态、总体积和重复文件名。
5. 大包异步生成，完成后提供有有效期的下载入口；失败不影响原结果。

## 10. 页面级 UI 设计说明

### 10.1 全局框架

- **左侧导航**：展开 220–240px，收起为图标栏；一级导航按“工作台—商品—生产—模板—任务—素材—设置”排序。
- **顶部栏**：企业切换、全局搜索/快捷入口、当前额度/预算预警、通知、主题与账号菜单。
- **内容区**：冷灰背景，白色/深色卡片，最大化利用桌面宽度；页面标题、说明、主操作置于首行。
- **反馈**：保存/提交期间按钮禁用并显示进度；长任务提交成功后立即跳转任务详情，不用全屏等待。

### 10.2 工作台

- 首行 4 个指标卡：运行中、待审核、失败、今日已完成。
- 中部左侧“快捷创建”：多模板图片包、营销视频、添加商品、打开画布。
- 中部右侧“队列状态”：排队数、预计等待提示、异常告警（仅有权限者）。
- 下部“最近任务”表格与“最近商品”卡片；点击可深链接到详情。
- 不使用大面积营销 Banner，突出生产效率。

### 10.3 商品列表

- 标题右侧主按钮“新建商品”，次操作“导入”（P1）。
- 顶部紧凑筛选条：关键词、品牌、类目、状态，右侧重置/刷新。
- 表格首列复选框，随后商品缩略图、编码/名称、品牌、类目、SKU 数、状态、最近生产、更新时间、操作。
- 勾选后底部或表格上方出现固定批量操作条：“生成图片”“生成视频”“启用/停用”“更多”。
- 行操作优先“查看/编辑”，危险删除放入更多菜单并二次确认。

### 10.4 商品详情

- 页头展示商品名称、编码、状态、品牌及快捷动作“生成图片/生成视频”。
- Tabs：基础信息、SKU 与参考图、历史任务、已通过素材。
- SKU 使用表格 + 右侧抽屉编辑；参考图用可排序缩略图墙，显示上传进度和失败重试。
- 离开未保存表单需提示；乐观锁冲突显示“重新加载/保留当前副本”，不可静默覆盖。

### 10.5 图片生产向导

采用 4 步步骤条，避免在单个超长表单堆叠：

1. **选商品**：商品/SKU 表格，可从商品列表预填。
2. **选模板**：按类型分组的模板卡片，多选；卡片显示平台、比例、默认数量和版本。
3. **配参数与预检**：左侧模板列表，中部参数，右侧实时统计；错误按商品/SKU 定位。
4. **预览并提交**：顶部切换预览 SKU，中部按模板展示输入卡，右侧固定显示总项数、预计消耗和提交按钮。

提交后跳到任务详情；草稿配置可保留在当前会话，P1 再支持命名保存为生产方案。

### 10.6 视频生产/工程页

- **左栏 280px**：商品素材、企业素材、上传素材 Tabs，支持搜索与拖入时间线。
- **中间主区**：16:9/9:16/1:1 播放预览；下方镜头时间线，镜头卡显示缩略图、时长、转场。
- **右栏 320px**：当前镜头/转场/字幕/BGM 属性面板，按选中对象切换。
- **底部或时间线旁**：总时长、自动编排、撤销/重做（若沿用画布能力）、低清预览、生成成片。
- 默认界面不暴露专业剪辑软件的复杂轨道；P0 使用一条主视觉轨 + 字幕 + 音乐三层语义。

### 10.7 模板中心

- 页头主按钮“新建模板”；图片/视频 Tabs，内置/企业来源筛选。
- 卡片或表格视图可切换：封面、模板名、类型、平台、规格、版本、状态、更新时间。
- 模板详情使用左右布局：左侧预览/示意，右侧基本信息与规则；提示词编辑区明确列出可用变量。
- 发布新版本需展示变更摘要与确认；旧版本以时间线/版本列表只读查看。

### 10.8 任务中心

- 顶部状态统计与筛选：类型、状态、商品、创建人、时间。
- 表格字段：任务名、类型、商品/SKU、模板数、进度、状态、创建人、消耗、创建时间、操作。
- 状态使用文本 + 图标/颜色，不仅依赖颜色；运行中显示进度条，部分成功需单独状态。
- 勾选后出现批量取消/重试/审核/导出；按钮根据所选项状态动态可用并说明跳过数量。

### 10.9 任务详情与审核

- 页头：状态、整体进度、创建人、模板/工程版本、消耗、取消/重试/导出。
- 左侧任务项筛选与缩略图网格/表格；右侧详情抽屉显示输入快照、错误、尝试记录。
- 图片审核支持 2–4 项大图对比；视频使用播放器并显示字幕/BGM/成片参数。
- 审核动作固定在可见区域，驳回弹窗必填原因；操作成功后自动跳到下一个待审核项。

### 10.10 平台管理员任务与运维页

- 延续现有 ProTable 高密度表格，增加队列健康摘要卡。
- 可按企业、任务类型、模型、Worker、状态和时间筛选。
- 错误信息默认展示脱敏摘要；详细日志按权限查看，不展示 API Key、签名 URL 或内部对象键。
- 运维动作（如重试、解除异常占用）必须二次确认并写审计记录。

## 11. 验收标准

### 11.1 图片闭环

1. 创建至少 2 个商品、每个 2 个 SKU，选择主图/轮播图/详情图 3 个模板、每模板 2 张，系统正确展示并创建 `2 × 2 × 3 × 2 = 24` 个任务项。
2. 同一请求因双击或响应丢失重放时只存在 1 个父任务、24 个任务项，并只预扣一次。
3. 任一 SKU 缺少模板要求的参考图时，提交前能定位具体 SKU；用户修正后无需重填其他配置。
4. 模板发布 v2 后，已创建的 v1 任务详情和重试仍使用 v1 快照。
5. 某一任务项失败时，父任务显示部分进度；重试只产生该失败项的新轮次，成功项不重复生成。
6. 审核通过结果可设主图、保存到企业素材并导出；压缩包路径包含商品编码、SKU 编码和模板类型，文件名不覆盖。

### 11.2 视频闭环

1. 用户可将至少 3 个图片/视频素材组成镜头，调整顺序并应用淡入淡出或交叉溶解。
2. 一段营销文案可自动分配到镜头，用户可修改每段字幕与时间；预览中字幕位于安全区。
3. 用户可添加 BGM，调整音量和淡入淡出，最终成片音频可正常播放；也可选择无 BGM。
4. 16:9、9:16、1:1 工程均能进入异步任务并生成 MP4；页面关闭后重新登录仍可查看状态和结果。
5. 最终合成失败时保留已成功的素材子项；重试合成不重复生成已有素材、不重复扣除已完成子项费用。
6. 修改已完成工程后再次生成会产生新版本，旧成片仍可预览与下载。

### 11.3 企业、权限与数据安全

1. 使用两个企业、两个账号验证商品、模板、任务、结果、媒体和导出严格隔离；伪造企业 Header/实体 ID 被服务端拒绝。
2. Member 不能发布模板或审核；Reviewer 不能编辑商品/模板或创建任务；Owner/Admin 权限符合角色表。
3. 成员被移除或切换企业后，旧页面刷新、轮询、下载链接均不能继续读取原企业私有数据。
4. 所有创建、编辑、发布、审核、批量导出和关键运维动作可在审计日志中关联操作者与资源。

### 11.4 并发、队列与恢复

1. 多 Worker 并发领取时同一任务项不重复执行；租约到期由新 Worker 接管后，旧 Worker 回写被拒绝。
2. 单个企业大量排队时，另一企业的小任务仍能被调度，不出现无限期饥饿。
3. 任务创建接口快速返回任务编号；长视频渲染不占用前端请求直到完成。
4. 上游 429、超时、Worker 重启和应用重启场景下，任务按规则重试或进入明确终态，无未知状态、重复结果和重复退款。
5. 运行任务状态在前端 5 秒内可见更新；完成后停止无意义高频轮询。
6. 管理后台能查看当前积压、运行、失败、平均/P95 耗时和 Worker 异常摘要。

### 11.5 存储与导出

1. 上游临时 URL 过期后，已归档结果仍能通过企业授权访问。
2. 删除/替换素材和存储 GC 不会删除仍被任务、画布、商品或导出引用的文件。
3. 导出超过限制、源文件缺失、无审核通过项时，系统不产生空包并提供可执行的错误提示。
4. 下载包不存在路径穿越、跨企业文件、签名 URL、API Key 或内部敏感配置。

### 11.6 UI 与兼容

1. Chrome/Edge 最新两个主版本，1440×900 与 1280×720 下完成商品—生成—审核—导出主流程，无关键按钮被遮挡。
2. 浅色/深色主题文字和状态可读；键盘可到达主要表单、列表操作与弹窗按钮。
3. 现有 `/image`、`/video`、`/canvas`、素材和历史任务仍可访问；旧企业模板能以兼容类型查看和使用。
4. 加载、空数据、无权限、网络失败、余额不足、提交成功均有明确状态，不能只在控制台报错。

## 12. 约束、依赖与风险

| 风险/依赖 | 影响 | 应对要求 |
|---|---|---|
| 已有企业与批量能力尚未完成 P0 验收 | 在未验证基础上扩展会放大隔离、计费、恢复风险 | 将现有 pending-test 中租户、计费、Worker、存储、备份项作为发布前置门槛 |
| 单次生成任务与批量任务存在两套用户认知/数据路径 | 状态、计费和历史可能不一致 | 产品层先统一任务状态、筛选和详情语义；兼容旧记录，避免强制迁移导致历史丢失 |
| 视频拼接/转码耗 CPU、内存与临时空间 | 高并发时易拖垮 API 服务 | 必须异步执行、限制输入与并发，并展示排队；部署细节由架构阶段确定 |
| 上游模型能力差异大 | 模板参数可能无法执行 | 模板与提交阶段做能力校验，隐藏不支持项并给出替代规格 |
| 上游临时 URL、CORS 或内网回源限制 | 视频/图片结果或参考素材不可持续访问 | 成功结果统一归档；提交前验证参考素材可访问性 |
| BGM 授权与内容合规 | 商用侵权或平台审核失败 | 默认要求用户确认拥有使用权；内置音乐必须有可追溯授权，内容审核可在 P1 增强 |
| 大批量导出耗时与磁盘占用 | 请求超时、临时文件堆积 | 大包异步处理、设置体积上限和有效期，完成/失败均清理临时文件 |
| 模板变量和历史版本兼容 | 更新后重试结果不可复现 | 任务固化模板版本、提示词与业务输入快照；历史版本只读 |
| SQLite 不适合 API + 多 Worker 高并发生产 | 锁竞争与可靠性下降 | 产品文档明确：本地/单机试用可用 SQLite，企业多实例生产应使用 MySQL/PostgreSQL |
| `/commerce` 单页体积和状态复杂度高 | 改造回归面大、页面难维护 | 增量增加独立页面，旧页作为兼容入口逐步收敛，不一次性删除 |
| AGPL-3.0 与二次开发标识要求 | 商业部署存在合规义务 | 发布前完成开源协议与原作者标识合规审查 |

## 13. 待确认事项与建议默认值

以下事项不阻塞 PRD/架构拆解；未收到业务确认时按“建议默认”执行：

1. **首期渠道范围**：是否仅淘宝、京东、抖音、小红书？
   - 建议默认：沿用现有四个平台交付规格，同时保留“原始结果/自定义规格”。
2. **主图、详情图、轮播图的模板定义**是否需要可视化布局编辑？
   - 建议默认：P0 采用元数据 + 提示词 + 预览图，不做自由画布式模板编辑；高级布局交给现有商品画布。
3. **详情图交付形式**是多张分段图还是拼成长图？
   - 建议默认：P0 输出有序分段图；拼接长图放 P1，避免超长图平台差异。
4. **轮播图槽位数**是否固定？
   - 建议默认：模板配置 3–10 个槽位，P0 以模板/结果排序表达，不强制每个平台统一数量。
5. **视频渲染规格**与单片最大时长？
   - 建议默认：MP4（H.264 + AAC）、1080p、16:9/9:16/1:1，单片 15–60 秒；更高分辨率或更长视频后续开放。
6. **字幕来源**是否必须支持自动语音识别/TTS？
   - 建议默认：P0 支持文案自动分镜 + 手工编辑；SRT/VTT、ASR、TTS 放 P1。
7. **BGM 来源**是否提供平台曲库？
   - 建议默认：P0 使用企业自有/上传音频并要求授权确认；无明确授权前不内置商业音乐。
8. **批量上限**是否调整？
   - 建议默认：沿用当前单任务 200 商品、5000 生产项、企业 10000 待处理项上限，支持配置但不在 UI 鼓励超大单。
9. **企业素材单文件限制**对成片是否继续为 80MB？
   - 建议默认：图片/参考素材沿用当前限制；成片上限与存储和渲染能力一起确认，可配置并在提交前展示。
10. **任务优先级/SLA**是否区分套餐？
    - 建议默认：P0 只做企业公平调度与统一优先级，套餐优先级放 P1。
11. **审核是否为强制交付门槛？**
    - 建议默认：企业可配置；默认图片/视频完成后进入待审核，只有审核通过结果进入标准批量导出，Owner/Admin 可切换为“完成即交付”。
12. **旧 `/commerce` 页面迁移策略**：是否允许调整路由？
    - 建议默认：保留旧入口和 API，增加新路由与导航；稳定后再做重定向和废弃提示。
