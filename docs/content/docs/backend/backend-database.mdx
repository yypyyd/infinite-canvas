### user_api_keys

用户对外调用 AI 接口的密钥表。密钥同时绑定创建用户和创建时的当前企业，每个用户在每个企业最多保留 10 个有效 Key。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 主键 |
| `organization_id` | string | Key 绑定的企业 ID |
| `user_id` | string | Key 创建用户 ID |
| `name` | string | 用户填写的用途名称，最多 50 个字符 |
| `prefix` | string | 用于列表辨认的非敏感前缀 |
| `key_hash` | string | 完整 Key 的 SHA-256 摘要，唯一索引，不通过接口返回 |
| `status` | string | `active` 或 `revoked` |
| `last_used_at` | string | 最近使用时间，最多每 5 分钟更新一次 |
| `revoked_at` | string | 撤销时间 |
| `created_at` | string | 创建时间 |
| `updated_at` | string | 最近更新时间 |

原始 Key 使用 32 字节密码学安全随机数生成，仅在创建成功响应中返回一次；服务端不保存明文，撤销后摘要不能再次鉴权。删除用户时会同步删除其 Key 记录。

### agent_sessions / agent_messages / agent_runs / agent_steps / agent_events

画布 Agent 的持久执行骨架。`agent_sessions` 按企业、用户和画布项目保存会话；`agent_messages` 保存有序消息；`agent_runs` 保存对应用户消息编号、`running`、`waiting_confirmation`、`waiting_tool` 与完成、失败、取消状态，并在隐藏 `context` 中固化本轮自主等级、画布快照和授权选区；`agent_steps` 保存 completion/tool 输入输出、工具调用编号、确认决定，以及模型步骤和画布工具的执行租约；`agent_events` 保存可恢复 SSE 事件。所有访问同时校验 `organization_id + user_id`。客户端会预分配会话与运行编号并先随画布保存，服务端对同编号同请求进行幂等重放、对冲突请求明确拒绝；Completion Step 由数据库原子认领，Tool Step 使用 90 秒租约并由执行页面每 30 秒续租，避免多实例或多标签页重复规划、生成、扣费和修改画布，执行页面失联后仍可接管。自主模式下首次非破坏性工具失败会保留为可观察的失败 Step 并恢复 Completion，允许模型修改参数重试一次；第二次失败仍结束 Run，相同参数始终禁止重放。当前开放图片/视频生成、图片/视频视觉验收、节点排列、文本插入、节点删除和文本覆盖；每个成功的图片或视频生成 Step 都必须由后续对应的 `image.inspect` 或 `video.inspect` Step 覆盖其实际节点编号，验收结论与问题保存在 Step 输出中，自主模式对每种媒体最多使用一次完整修订提示词重新生成。删除与覆盖只有持久化批准后才转入 `waiting_tool`，拒绝则记录未执行 observation。画布历史撤销 Agent 工具副作用时会幂等追加 `tool.reverted` 事件；仍在执行或等待后续工具的 Run 同时转为 `cancelled`，避免模型继续基于已回滚结果规划。媒体结果只保存节点编号和私有 `storageKey`，不保存二进制或签名 URL。`waiting_tool` 超过 15 分钟会定时或惰性回收，`waiting_confirmation` 则保持等待用户明确决定。

### agent_memories

Agent 的长期记忆表。记忆同时绑定企业、用户和可选画布项目；`project_id` 为空表示账号级记忆，否则只会在该画布项目的 Run 中检索。`kind` 取 `preference`、`fact`、`constraint` 或 `experience`，`key` 在同一企业/用户/项目范围内作为稳定覆盖键，`content` 保存可注入模型上下文的短文本，`confidence` 用于检索排序，`source_run_id` 和 `source_message_id` 保留来源，`expires_at` 支持自动过期。`active` 记录会注入后续 Run；用户批准 `agent.forget` 后改为 `forgotten` 并保留遗忘时间，永不再注入。所有写入由服务端从已确认的模型工具参数生成，浏览器不能提交任意记忆内容；读取、覆盖和遗忘均校验 `organization_id + user_id`，避免跨企业、跨账号或跨项目泄漏。

### organizations / organization_members

企业租户和成员关系表。一个用户可以加入多个企业，`users.organization_id` 只保存新会话默认/最近使用的企业。登录后的企业 API 请求携带 `X-Organization-ID`；浏览器原生图片、视频和下载请求无法自定义 Header，因此媒体 URL 使用 `organization` 查询参数携带企业 ID。后端中间件会逐请求校验企业状态和成员关系，再把企业上下文传给画布、媒体、模型任务和电商业务，多个浏览器标签页可各自保持独立企业上下文。

`organizations` 保存企业名称、唯一标识、状态、创建人和创建时间；`credit_mode` 决定生成任务使用成员个人额度还是企业共享额度，`credits` 保存共享余额，`monthly_credit_budget`、`monthly_credits_used`、`credit_budget_month` 和 `credit_alert_threshold` 保存月度预算、当月用量、预算月份与预警比例。月度预算为 0 时不限制；进入新月份时在首笔扣费或设置更新事务中重置当月用量。仅服务端使用的 `batch_claim_cursor` 记录该企业最近一次领取批量生产项的顺序游标。`organization_members` 通过 `organization_id + user_id` 联合唯一索引关联成员，角色包括 `owner`、`admin`、`member`、`reviewer`。企业与成员关系均保存 `version` 乐观版本号；企业设置、额度设置、成员角色、成员移除和所有权转移必须提交读取时版本，拒绝多个管理员基于旧页面静默覆盖。企业所有者可以转移所有权，管理员不能修改或移除所有者。

### organization_invitations / organization_email_outboxes / organization_audit_logs

企业邀请保存受邀邮箱、角色、状态、邀请人和过期时间；状态包括 `pending`、`accepted`、`revoked`、`expired`，查询和再次邀请时会先把过期记录原子标记为 `expired`。邀请与 `organization_email_outboxes` 邮件事件在同一事务创建，后台 Worker 通过租约原子领取并使用 SMTP 发送，失败后指数退避，进程退出或租约过期后可重新接管；接受、撤销或过期的邀请会取消尚未发送的事件。邀请接受时以待接受状态和过期时间为条件原子更新，再创建成员关系并切换默认企业，避免撤销与接受并发穿透。审计日志按企业记录成员、品牌、商品、SKU、批量任务和画布保存等操作，并与对应业务写入处于同一数据库事务，普通成员不可读取。

### brands

企业品牌规范表，按 `organization_id` 隔离，保存 Logo 的企业私有 `storageKey`、品牌色、字体、品牌语气、视觉规范和禁用词。企业内品牌名称使用联合唯一索引；Logo 文件引用与品牌保存处于同一事务。品牌使用 `version` 乐观版本号，保存和删除必须提交读取时版本，其他成员已保存新版本时拒绝静默覆盖或误删。

### products / product_skus

企业商品主数据表。`products` 保存 SPU 编码、品牌、类目、卖点、目标人群和状态；`product_skus` 保存 SKU 编码、规格属性、企业私有参考图 `storageKey` 和状态。SPU、SKU 编码均在企业内唯一，SKU 创建后不能变更所属商品；两张表均使用 `version` 乐观版本号和条件更新，保存和删除都必须提交读取时版本，拒绝基于旧版本的并发覆盖或误删。商品作为 SKU 聚合根，SKU 创建、更新或删除会在同一事务递增所属商品版本，因此旧商品列表不能级联删除其他成员刚变更的 SKU。品牌、商品或 SKU 已被商品主数据或批量生产历史引用时拒绝删除；写入、任务创建和删除会锁定相同父级记录，避免并发产生悬空引用。SKU 参考图引用与 SKU 保存处于同一事务，删除 SKU 或包含它的商品时同步释放引用，并从实际删除时间开始计算 24 小时文件回收宽限期。

### production_templates / production_template_versions

企业自定义生产模板及不可变版本。`production_templates` 保存企业内唯一名称、说明、来源、媒体类型、模板类型、平台、草稿/启用/停用状态、当前版本号和乐观 `version`；每次保存都必须提交读取时版本，并在同一事务新增一条 `production_template_versions`，版本同时冻结提示词和规格 JSON，历史内容不原地修改。模板变量只允许服务端白名单字段，不执行函数或表达式。所有者和管理员可以发布新版本，其他角色只读。批量任务保存模板编号、明确版本及创建时完整提示词，后续启停或发布新版不改变已提交任务；提示词预览和 Worker 共用同一拼装逻辑，在模板指令后注入本企业品牌、商品和 SKU 快照信息。

### batch_production_jobs / batch_production_template_selections / batch_production_items / batch_production_snapshots

企业批量生产任务及任务项。新图片包请求使用商品范围（全部有效 SKU 或指定 SKU）和多个模板选择；`batch_production_template_selections` 冻结模板 ID/版本/类型、数量、提示词、规格 JSON 和交付规格，任务项按 `SKU × 模板选择 × variant_index` 展开，由服务端在单事务中按确定性 Item ID 写入，配合父任务 `organization_id + request_id` 幂等唯一键防止重复展开。父任务新增图片包类型、排队/运行计数和 `pending_review`、`partial_success` 聚合状态；旧单模板字段保留兼容读取。创建接口要求客户端生成 `request_id`，并通过 `organization_id + request_id` 联合唯一索引保证超时重试、双击和代理重放只创建一次任务；`request_hash` 保存规范化名称、品牌、模板编号与版本、渠道交付规格和商品集合的 SHA-256 摘要，同请求号只有摘要一致时才返回已有任务，不同内容会返回冲突。每个任务还保存仅服务端可见的随机 `archive_token`、`preset_version`、创建时的 `preset_prompt` 和以 `delivery_` 为前缀嵌入的交付规格快照，分别用于隔离 Worker 归档文件命名空间、冻结本次生产模板，以及固定平台、名称、宽高、格式、质量和文件命名规则。幂等查询在商品和 SKU 展开前完成，成功响应丢失后的重试不会受后续主数据变化影响。首次创建会先锁定企业和所选商品，再在同一事务读取并展开完整 SKU 集合；没有 SKU 的商品按 SPU 创建任务项，因此并发新增 SKU 不会落在事务读取与任务写入之间。`batch_production_snapshots` 按任务分别保存一份品牌快照、每个商品快照和每个 SKU 快照，任务项只保存三个快照 ID，避免为每个生产项重复存储整包输入；单任务最多 5000 个生产项，单企业处于 `queued` 或 `running` 的生产项合计最多 10000 个，创建和人工重试均在企业锁内检查上限。去重后的快照总量限制为 16MB，后续主数据修改不会改变已经提交的生产输入。

### video_projects / video_project_versions

视频工程基础表按企业隔离。`video_projects` 保存名称、描述、商品/SKU 关联、可变草稿 Timeline JSON、草稿乐观 `version` 和当前冻结版本号 `current_version`；Timeline JSON 包含有序镜头素材与时长、转场、字幕、BGM 引用和音量、输出规格，只持久化企业文件 `storageKey`。保存草稿使用 `organization_id + id + version` 条件更新，草稿文件以 `video_project_draft` 引用域保护。`video_project_versions` 保存不可变 Timeline 与输出规格快照，以企业、工程、版本联合唯一；发布事务创建新快照并同时递增工程的 `current_version` 和乐观 `version`，版本文件以 `video_project_version` 引用域保护。历史版本只有列表和详情读取入口，不提供更新或删除。Release 1 不存在视频渲染任务表，也不创建无法消费的排队任务。

任务项支持 `queued`、`running`、`completed`、`failed`、`cancelled` 状态、不可伪造的 `lease_token`、`lease_expires_at`、尝试次数、结果地址和错误信息；完成项还保存 `pending`、`approved`、`rejected` 审核状态、批注、审核人、审核时间和主图标记。同一任务内每个商品最多一个主图；失败项或已驳回项重新生成时递增 `run_number`，清空旧结果和审核信息并解除旧文件引用，审核、重试和主图选择都提交当前生产轮次以拒绝旧页面覆盖新结果。

独立 `batch-worker` 进程通过数据库条件更新原子领取，每 2 分钟续租。默认内置标准执行器读取任务创建时固化的品牌、商品和 SKU 快照，按 `preset_id` 组装固定电商模板，并复用后台默认图片模型、渠道能力和用户组计费规则；没有参考图时调用 OpenAI 兼容生图接口，存在参考图时最多读取 4 张、单张不超过 20MB 的 Kodo 私有图片并通过 `image[]` 调用编辑接口。GPT Image 的 `b64_json` 和 DALL·E 类短期 URL 结果都会在 Worker 内限制大小、识别真实图片类型并归档，生成任务从预扣开始覆盖上游调用、结果下载、Kodo 归档和任务项完成，任一阶段失败均使用原有事务规则退款。配置 `BATCH_WORKER_EXECUTOR_URL` 与 `BATCH_WORKER_TOKEN` 后可切换到外部执行器，外部执行器接收快照、模板、任务项及 30 分钟私有媒体地址，并返回 `resultUrl`、`mimeType` 和 `size`。两类执行器的结果都在 Worker 公共归档边界按任务快照执行居中裁切、缩放和 JPEG/PNG 转码；需要变换的外部结果先通过拒绝私网解析、受限重定向、声明大小和真实 MIME 校验下载，因此外部执行器不需要自行实现渠道后处理。

领取按企业最近领取游标轮转，再在企业内按创建顺序领取，避免单个大租户长期占满全局 FIFO；候选企业使用索引顺序和相关 `EXISTS` 判断，不再为每个生产项聚合、排序全局队列。领取、续租、取消、完成和超时归档统一先锁企业；`BATCH_WORKER_TENANT_CONCURRENCY` 限制单企业同时运行数量，默认 2 且不会超过 `BATCH_WORKER_CONCURRENCY`。标准执行器和外部执行器均使用“任务项 ID + `run_number`”派生稳定请求号，同一轮租约接管保持幂等，人工重试递增轮次后允许真正重跑；携带 API Key 或 Bearer Token 的请求完全禁止跟随重定向。Worker 在归档前同步确认租约，外部结果和标准执行器 URL 结果均通过拒绝私网解析、限制重定向和任务 Context 控制的读取获取；七牛上传凭证强制精确大小、媒体类型和对象键。归档文件使用“任务随机 `archive_token` + 任务项 ID + `run_number`”确定的稳定 `storageKey`，`batch-result-` 前缀禁止从用户上传入口创建，进程在文件确认后、任务完成前退出时，租约重投递会复用已校验结果而不是重复占用企业额度。校验成功后结果写入 `organizations/{organizationId}/batch-results/`，在企业额度事务中确认文件，并让任务项保存 `result_storage_key` 和事务型文件引用。任务项只持久化固定安全错误文案，服务日志只记录任务项和错误类型，不保存外部 URL、签名参数、内部地址或上游错误原文。连续 5 次租约超时会自动失败，人工重试会开启新的尝试周期；取消会清空租约并中止仍在进行的结果读取或上传。可通过 Docker Compose `worker` profile 启动；正式环境应让 API 与 Worker 共用 MySQL 或 PostgreSQL，不使用 SQLite 承载多进程生产队列。租约和业务时间统一保存为固定九位小数的 UTC RFC3339，保证字符串条件比较与时间先后一致。

### users

系统用户表。用户基础信息、角色、人民币账户余额和算力点余额放在该表中；两种余额互不兑换、互不抵扣。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 主键 |
| `username` | string | 用户名，唯一索引 |
| `password` | string | 密码哈希 |
| `email` | string | 邮箱 |
| `email_key` | nullable string | 规范化邮箱唯一键；历史空值为 `NULL`，新注册用户用于防止并发重复注册 |
| `display_name` | string | 昵称 |
| `avatar_url` | string | 头像地址 |
| `organization_id` | string | 新会话默认/最近使用的企业 ID，不作为业务请求的唯一租户上下文 |
| `role` | string | 角色：`user`、`admin` |
| `group` | string | 用户计费分组，默认 `default` |
| `balance_cents` | number | 人民币账户余额，单位分，与算力点独立 |
| `credits` | number | 算力点余额 |
| `aff_code` | string | 用户自己的邀请码，唯一索引 |
| `aff_count` | number | 已邀请用户数量，冗余统计字段 |
| `inviter_id` | string | 邀请人用户 ID |
| `github_id` | string | GitHub 用户 ID |
| `linux_do_id` | string | 历史预留字段，当前登录流程不再使用 |
| `wechat_id` | string | 微信用户 ID |
| `status` | string | 用户状态：`active`、`ban` |
| `last_login_at` | string | 最近登录时间 |

### balance_logs

人民币账户余额的独立资金流水表。易支付订单成功时与订单状态和 `users.balance_cents` 在同一事务中写入；邀请返佣会与返佣明细和邀请人余额在同一事务中写入；余额兑换算力时，本表记录人民币扣减，`credit_logs` 记录个人算力增加，两条流水和两侧余额在同一事务中提交。本表不把算力点记作人民币金额，`credit_logs` 也不把人民币金额记作算力。

| `updated_at` | string | 更新时间 |

创建任务时会按企业当时的 `credit_mode` 固化 `credit_source`。`generation_tasks`、个人或企业算力预扣和 `ai_consume` 流水在同一事务中提交，任一步失败都会整体回滚；共享模式同时检查企业算力与月度预算，消费流水的 `related_id` 保存任务 ID。客户端可通过 `Idempotency-Key` 提交稳定请求编号，同一企业、用户和请求编号只能创建一个任务，重复请求不会再次扣费。任务失败时，失败终态、原扣费来源算力返还和 `ai_refund` 流水同样在一个事务中提交，并只允许 `running` 任务进入失败终态，因此切换扣费模式或重复失败回调不会退错算力账本或重复退款。同月退款减少当月用量，跨月退款只增加共享算力。

图片和视频请求会在任务表中保存稳定请求编号、原渠道、上游任务 ID、可恢复响应和已归档文件编号。生成成功后由后端直接写入七牛，并以生成任务 ID 构造稳定文件编号；重复轮询和刷新恢复复用同一文件，不再要求浏览器下载后重新上传。浏览器刷新后从服务端工作区读取“生成中”记录，再按请求编号接管原任务；视频状态和内容查询固定使用任务创建时的渠道，明确失败时才进入失败终态，避免刷新后改选渠道、重复提交、重复扣费或丢失结果。恢复接口按当前企业和用户双重隔离，不返回渠道密钥；生成记录成功写入工作区后，前端确认消费恢复结果，服务端清空临时响应和文件编号并把文件引用交给正式生成记录。

### user_files / user_file_upload_reservations / user_file_upload_rate_limits / user_file_references / user_object_deletions

企业媒体文件及其上传、引用和回收状态。文件本体可保存在七牛云 Kodo 私有空间或服务端本地持久化目录，数据库保存企业鉴权、存储驱动、对象定位和读取所需的元数据。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 主键 |
| `organization_id` | string | 所属企业 ID |
| `user_id` | string | 上传用户 ID |
| `storage_key` | string | 前端媒体存储编号；与 `organization_id` 组成联合唯一索引 |
| `storage_driver` | string | 实际存储驱动：`qiniu` 或 `local`；切换全局设置后旧文件仍按此字段读取和清理 |
| `object_key` | string | 存储驱动内部的相对对象键，不通过接口返回 |
| `hash` | string | 存储驱动返回的权威内容哈希：七牛 ETag 或本地文件 SHA-256 |
| `mime_type` | string | 媒体 MIME 类型 |
| `size` | number | 文件字节数 |
| `unreferenced_at` | string | 首次确认没有业务对象引用的时间；重新被引用时清空 |
| `created_at` | string | 创建时间 |
| `updated_at` | string | 更新时间 |

单文件上限为 80MB，`storageKey` 最长 191 字节；企业默认额度由 `USER_STORAGE_QUOTA_MB` 配置，默认 5120MB。申请上传时，后端锁定企业记录，在 `user_file_upload_reservations` 中原子预留新增空间并同时计算其他待上传预留，防止多成员并发突破企业额度。企业最多保存 100000 个正式文件、同时持有 512 个有效上传预留和 10000 个“有效预留 + 待删除对象”，单用户最多同时持有 64 个有效预留和 1000 个临时对象，避免小文件绕过字节额度放大数据库记录。预留的 `cleanup_reserved_bytes` 按“本次对象大小”和“可能被替换的旧对象大小”取较大值；`user_object_deletions` 同时保存企业、用户及对象字节数。有效预留的潜在清理字节与待删除对象字节合计不得超过同一企业额度，从而把仍有效但已取消或被取代的上传凭证也纳入物理临时空间上限。过期预留和正式文件 GC 每次最多处理 500 条，并使用企业、到期时间及无引用时间复合索引。浏览器上传凭证和预留有效期为 20 分钟，覆盖 15 分钟客户端上传上限及确认余量；用户中止或上传失败后会通过鉴权取消接口立即释放逻辑预留。未确认临时对象不会立即删除，而是在凭证过期后再保留 15 分钟在途上传宽限，避免删除任务先收到“对象不存在”、随后上传完成而形成孤儿对象。每次上传都使用 `organizations/{organizationId}/uploads/{uploadId}` 下的唯一临时对象键；相同 `storageKey` 不会跳过本次内容校验，确认时以后端读取的驱动权威哈希和实际大小判定是否复用旧文件，内容不同会清理临时对象并返回编号冲突。只有旧对象确实缺失或权威元数据与数据库不一致时才允许修复替换，预留同时绑定被修复的原对象键，避免并发修复覆盖其他成员刚确认的新文件。有效预留会阻止同一 `storageKey` 的旧文件被 GC；七牛上传策略和本地写入入口都会校验大小与媒体大类，确认阶段再次核对对象实际媒体大类与存储编号，避免图片编号挂接视频或音频。HEAD 健康检查同时核对数据库哈希、存储驱动权威哈希、大小和媒体大类，同大小的错误内容不会被视为健康文件。上传确认还会在企业锁内按当前文件、其他预留和实际大小重新计算额度，避免旧文件回收后差额预留失真。上传完成后由后端读取对象元数据，在同一事务中确认 `user_files`、释放预留并把待清理对象写入删除队列；七牛凭据只保存在服务端私有设置或环境变量中。

`user_file_references` 在画布、素材、生成记录、品牌、SKU、批量输入快照和批量结果保存事务中按业务对象替换 `storage_key` 引用，并在写入前验证文件已确认存在。文件确认、引用替换、上传预留创建、取消和过期都会在同一企业锁事务中即时写入或清空 `unreferenced_at`；后台只按索引扫描已到期记录，不再周期性反查全部正常文件。无引用文件按私有设置中的 `retentionDays` 删除，`0` 表示不自动删除正式文件。业务请求只提交删除事件，不直接调用存储后端；对象删除完全由后台 Worker 使用租约领取、指数退避和幂等“对象不存在即成功”语义执行，并按删除记录中的 `storage_driver` 选择七牛或本地。七牛浏览器直传和本地同源上传均具有 15 分钟客户端上限并可取消；文件读取必须先通过当前企业成员鉴权，七牛返回短期私有下载地址，本地文件由同源后端流式返回，不能跨企业访问。

`user_file_upload_rate_limits` 按企业和用户分别保存当前分钟窗口计数；企业每分钟最多申请 600 个上传凭证，单用户每分钟最多申请 120 个。计数与企业行锁配合，在多 API 实例下保持一致；达到上限后的请求不会继续执行对象状态检查和上传预留事务。

存储驱动与保留策略保存在 `private.storage`。环境变量 `QINIU_ACCESS_KEY`、`QINIU_SECRET_KEY`、`QINIU_BUCKET`、`QINIU_REGION`、`QINIU_DOWNLOAD_DOMAIN` 和 `LOCAL_STORAGE_PATH` 仅作为对应字段未填写时的服务端默认值；七牛下载域名必须是无用户信息的完整 HTTPS URL，本地目录不能是磁盘根目录。
