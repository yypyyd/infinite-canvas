# Adobe GPT Image 2 纯协议生图

GPT Image 2 在每次生成前通过 HTTP 获取新的 Arkose 生成会话，不再依赖注册端提供的 ARP，也不使用随机拼接的 `sid/ftr` 作为该模型的提交凭据。运行时不会启动 Chromium、Playwright 或远程浏览器。

## 调用流程

1. 账号池从导入的 Cookie 交换 IMS access token，沿用既有账号出口策略。
2. Adobe provider 获取官方 Arkose SDK；只在内存缓存公开脚本一小时，不缓存账号生成令牌。
3. Node.js 使用内置协议画像运行 SDK 的序列化与加密部分。时间戳、会话 ID、SDK 构建号现场生成或读取，不传入账号 Cookie、密码或 IMS token。最多同时运行四个加密子进程，单次限时 12 秒。
4. Go/TLS 客户端使用同一出口提交握手，取得服务端签发的被动验证令牌。只有正确站点、`sup=1` 且无交互挑战/工作量证明的响应可用于生成。
5. 提交 `gpt-image` / `modelVersion=2`，使用提示词前 256 个 UTF-16 单元计算 nonce，轮询任务并下载图片。
6. 仅提交阶段明确返回 `timeout_error / system under load` 时刷新一次生成会话。已经取得任务链接、网络结果不明或下载失败时不会因此重新提交图片任务。

Node.js 22+ 是 SDK 计算运行时，不是浏览器依赖；项目 Docker 镜像本来已包含 Node。直接运行 Go 时需确保 `node` 在 PATH，或设置 `ADOBE_NODE_BINARY` 为可执行文件路径。SDK 结构变化、Node 缺失或上游要求交互验证会明确返回生成会话错误，不伪造令牌、不把登录账号标为永久失效。

该实现适配当前 SDK 加密入口；上游脚本结构更新后可能需要调整适配。没有新增第三方打码服务、额外 API Key 或浏览器服务作为运行依赖。

## 已验证

在用户提供的服务器上运行项目实际 Go 客户端，输入只有原始导出 Cookie 的账号 #87，分别完成：

| 场景 | 输出 | 验证 |
| --- | --- | --- |
| 文生图，1:1，低质量 | PNG，1024×1024，1,251,017 字节 | 下载并完整解码 |
| 单参考图编辑，16:9，中质量 | PNG，1376×768，1,367,494 字节 | 下载并完整解码，蓝杯保持、场景改为木桌与绿植 |

旧实现错误地用 1K/2K/4K 表示 `detailLevel`，实际像素尺寸没有变化。当前已分离：`resolution` 控制尺寸，`quality` 控制细节质量，low/medium 对应 1/3，auto 默认 medium。免费账号实际请求 2K + low 已下载并完整解码为 2048×2048 PNG（4,956,303 字节）；high 被上游以 `user_not_entitled` 拒绝。非方图按既有 1K 比例预设放大边长两倍得到 2K，定价继续按像素档而非质量档。

这两次运行没有输入密码、没有启动浏览器、没有提供抓取的 ARP。临时排障中使用的浏览器会话仅用于协议对照，未进入最终验收输入。独立测试工具、临时分析素材和生成的测试图片已按要求清理。

相关网关测试及主程序构建通过。仍需按待测试清单完成生产部署后的页面、批量和多实例验收；以上结果不表示线上镜像已经更新。

## 实际功能验收

独立测试命令已移除。后续在账号池导入 Cookie，从画布选择 Adobe GPT Image 2 分别进行文生图和参考图编辑，并确认结果可以下载、打开。需要代理时使用后台现有 Adobe 渠道配置。成功生成会消耗该账号的额度。

## 错误与权限

- Cookie 换 token 成功仅代表登录有效，不能证明模型权限和额度。
- `generation_session_unavailable`：SDK 计算、获取或验证失败，检查 Node 与上游版本；账号保持可恢复。
- `timeout_error`：一次会话刷新后仍被上游拒绝，保留临时错误分类，不无限重试。
- `trial_exhausted`：Adobe 确认免费试用已用完；需要在官网确认额度或升级计划，不能承诺每日自动恢复。
- 401、内容审核、已受理任务的轮询和结果下载继续沿用现有错误处理、归档与计费流程。
