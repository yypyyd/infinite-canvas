# Docker 部署

如果你希望在自己的机器或服务器上运行项目，可以直接使用 Docker Compose。

## 从当前源码启动

```bash
git clone https://github.com/yypyyd/infinite-canvas.git
cd infinite-canvas
cp .env.example .env
# 编辑 .env，填写至少 12 位的 ADMIN_PASSWORD 和至少 32 位的 JWT_SECRET
docker compose up -d --build
```

启动后访问：

```text
http://localhost:3000
```

首次启动管理员账号：

```text
用户名：admin
密码：.env 中的 ADMIN_PASSWORD
```

## 使用已有发布镜像

已有发布镜像时，可指定镜像地址并省略本地构建：

```bash
INFINITE_CANVAS_IMAGE=ghcr.io/your-name/infinite-canvas:tag docker compose up -d
```

`NEXT_PUBLIC_DOC_URL`、`NEXT_PUBLIC_REPOSITORY_URL` 和 `NEXT_PUBLIC_VERSION_URL` 会在构建前端镜像时写入。

## 文档站镜像

文档站位于 `docs/` 目录，按带服务端能力的 Next.js standalone 应用单独构建，不打进主应用镜像。

从当前源码构建：

```bash
cd docs
docker compose up -d --build
```

使用已有发布镜像：

```bash
cd docs
INFINITE_CANVAS_DOCS_IMAGE=ghcr.io/your-name/infinite-canvas-docs:tag docker compose up -d
```

## 数据目录

`docker-compose.yml` 会把本地 `./data` 挂载到容器内 `/app/data`，用于保存 SQLite 数据库、提示词数据和上传素材。

Docker 部署时建议把 `.env` 中的 SQLite 路径设置为：

```text
DATABASE_DSN=/app/data/infinite-canvas.db
```

如果需要让模型上游拉取本地上传的参考素材，或启用易支付回调，还需要把 `PUBLIC_BASE_URL` 设置为公网可访问的站点地址。

## 批量生产 Worker

正式环境先配置 MySQL 或 PostgreSQL、七牛 Kodo 或共享本地持久化目录、后台默认图片模型及对应计费规则，再启动独立 Worker：

```bash
docker compose --profile worker up -d
```

Worker 默认使用内置标准执行器：根据任务创建时固化的品牌、商品和 SKU 快照组装生产模板，普通任务调用默认图片模型的生图接口，有参考图时调用多图编辑接口；生成结果完成校验后归档到当前配置的文件存储，并沿用生成任务的预扣、成功结算和失败退款规则。本地模式下应用与独立 Worker 必须挂载同一个持久化目录。

如需使用自有生产服务，可同时配置 `BATCH_WORKER_EXECUTOR_URL` 和 `BATCH_WORKER_TOKEN` 切换到外部执行器模式。外部执行器必须按请求中的 `Idempotency-Key` 幂等处理，并返回 `resultUrl`、`mimeType` 和 `size`。

## 生产自动部署

线上站点由 Nginx 反代本机 `127.0.0.1:3050`，数据在 `/opt/infinite-canvas/data`，环境变量在 `/opt/infinite-canvas/.env`。不要用仓库根目录的 Compose 去占用 3000。

推送到 `main` 或打 `v*` 标签后，GitHub Actions 会构建 `ghcr.io/yypyyd/infinite-canvas`，再 SSH 到生产机执行 `scripts/deploy-production.sh`：拉取镜像、备份当前 SQLite、把旧容器改名为 `infinite-canvas-rollback`、新容器以固定名 `infinite-canvas` 占 3050，健康检查失败则切回。`main` 部署镜像标签是 `main`，版本标签部署同名版本。部署成功后只保留当前和回滚这两份幻图镜像，更旧的版本镜像会删掉；SQLite 部署备份只留最近两份。

仓库 Actions 需要这些 Secret：

- `DEPLOY_HOST`：生产机地址
- `DEPLOY_USER`：SSH 用户
- `DEPLOY_SSH_KEY`：仅用于部署的私钥
- `GHCR_READ_TOKEN`：镜像私有时填写只读 token；公开镜像可留空
- `GHCR_USERNAME`：可选，默认仓库所有者

GitHub 环境名是 `production`，需要人工确认时在该环境打开 Required reviewers。回滚或热修走 Actions 的 `workflow_dispatch`，填写已有镜像标签即可，不会重新构建。

首次接通：本机生成 ed25519 密钥，公钥写入生产机 `authorized_keys`，私钥放进 `DEPLOY_SSH_KEY`。生产机先能 `docker pull` 对应镜像，再手动跑一次：

```bash
TAG=v0.2.17 /opt/infinite-canvas/deploy-production.sh
```

## 备份

应用镜像内置数据库与七牛 Kodo 备份恢复命令；本地文件存储需要同时备份挂载的数据目录。生产操作前必须停止应用和批量 Worker，完整命令、校验规则和恢复演练见[备份与恢复](./backup-restore)。
