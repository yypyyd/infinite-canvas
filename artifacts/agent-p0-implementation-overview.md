# 画布 Agent 能力实施概览

## 已完成

- 在现有 Go/Gin/GORM + Next.js/React 架构内实现 Agent 会话、消息、运行、步骤与 SSE 事件持久化。
- 接入 OpenAI-compatible 模型调用，并复用现有渠道、计费、退款和企业/用户隔离链路。
- 开放六个严格白名单工具：`image.generate`、`video.generate`、`canvas.arrange`、`canvas.add_text`、`canvas.delete`、`canvas.update_text`。
- 删除和文本覆盖必须经过持久化用户确认；前端执行前再次校验授权选区、节点类型与批次节点限制。
- 工具真实执行结果作为 observation 回传，Agent 再进行第二轮总结，不允许在工具返回前虚报完成。

## 恢复与幂等

- 助手消息随画布项目保存 `runId` 和最后 SSE 事件序号；刷新后会补放未消费事件并续接未完成运行。
- 所有画布工具将副作用结果写入项目级 `${runId}:${callId}` 回执并强制同步，之后才提交 Tool Result。
- 服务端提供 Tool Step 回执查询；相同结果重复提交幂等成功，不同结果重复提交明确拒绝。
- 会话 ID 与运行 ID 由客户端预分配并先持久化；服务端对同请求重放返回既有记录，对冲突请求拒绝复用。
- 图片和视频创建请求使用稳定的 `agent:${runId}:${callId}` 幂等键。

## 并发安全

- Completion Step 使用数据库条件更新认领，阻止同一 Run 在多实例中重复调用规划或总结模型。
- Tool Step 使用 90 秒数据库执行租约，前端每 30 秒续租；另一个标签页不能同时执行同一工具。
- Tool Result 必须携带当前执行令牌，数据库按令牌 fencing 提交；失去租约的旧执行者不能落库结果。
- 媒体请求支持 AbortSignal；心跳失败会中止可取消请求，并在插入节点、保存项目回执和提交结果前重新验租约。
- `waiting_tool` 最长等待 15 分钟，正常进程主动回收，服务重启后通过查询、SSE 或结果提交惰性回收。

## 文档与数据库

- 已同步 `CHANGELOG.md`、待测清单、TODO 和数据库说明。
- Agent Step 新增执行租约字段，Agent Run 保存对应用户消息 ID；已纳入现有 GORM AutoMigrate。
- 画布工具回执保存在现有项目 JSON 中，没有为此新增独立数据表。

## 静态检查结果

- `git diff --check` 通过，仅有 Windows 工作区 LF/CRLF 提示，不属于差异错误。
- 已静态核对 `executionToken` 从前端 API、Service 到 Repository 条件更新的完整链路。
- 已静态核对 Completion 认领、Tool 租约心跳、稳定媒体幂等键与刷新恢复链路。
- 按项目约定，没有运行构建、测试或编译。

## 建议手动验收

1. 工具副作用完成后、Tool Result 回传前立即刷新，确认只补交结果、不重复生成或修改节点。
2. 同一画布在两个标签页同时收到同一个 `tool.call`，确认只有一个页面取得执行权。
3. 执行页面关闭后等待租约过期，确认另一页面可以接管；旧页面恢复后不能提交结果。
4. 图片/视频请求成功但响应丢失时，确认稳定幂等键不会重复计费或重复创建任务。
5. Agent Run 已终态但本地事件游标落后时刷新，确认最终消息与尾部事件仍会补放。
6. 删除/文本覆盖批准、拒绝、重复确认和相反确认均保持已持久化决定。
7. `waiting_tool` 超过 15 分钟后只产生一次失败终态，迟到结果不能恢复运行。

## 已知边界

- 画布项目保存与 Agent 关系型事务无法组成单一跨存储事务；当前通过 durable-before-ack、项目回执、稳定幂等键和服务端 fencing 缩小并覆盖主要重复副作用窗口。
- 本轮只完成静态检查，实际浏览器、多标签页、网络中断和服务重启场景仍需按待测清单验收。
