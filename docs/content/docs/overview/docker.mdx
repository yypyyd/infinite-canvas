# Docker 部署

如果你希望在自己的机器或服务器上运行项目，可以直接使用 Docker Compose。

## 使用发布镜像

```bash
git clone https://github.com/yypyyd/infinite-canvas.git
cd infinite-canvas
cp .env.example .env
# 编辑 .env，填写至少 12 位的 ADMIN_PASSWORD 和至少 32 位的 JWT_SECRET
docker compose up -d
```

启动后访问：

```text
http://localhost:3000
```

首次启动管理员账号：

```text
用户名：admin
密码：.env 中的 ADMIN_PASSWORD
```

## 本地构建镜像

如果需要基于当前源码构建镜像：

```bash
cp .env.example .env
docker compose -f docker-compose.local.yml up -d --build
```

`NEXT_PUBLIC_DOC_URL`、`NEXT_PUBLIC_REPOSITORY_URL`、`NEXT_PUBLIC_VERSION_URL` 和 `NEXT_PUBLIC_CREDIT_PURCHASE_URL` 会在构建前端镜像时写入。自托管如需隐藏原项目作者维护的算力购买入口，可在构建前把 `NEXT_PUBLIC_CREDIT_PURCHASE_URL` 设为 `off`。

## 文档站镜像

文档站位于 `docs/` 目录，按带服务端能力的 Next.js standalone 应用单独构建，不打进主应用镜像。

使用发布镜像：

```bash
cd docs
docker compose up -d
```

基于当前源码本地构建：

```bash
cd docs
docker compose -f docker-compose.local.yml up -d --build
```

## 数据目录

`docker-compose.yml` 会把本地 `./data` 挂载到容器内 `/app/data`，用于保存 SQLite 数据库、提示词数据和上传素材。

Docker 部署时建议把 `.env` 中的 SQLite 路径设置为：

```text
DATABASE_DSN=/app/data/infinite-canvas.db
```

如果需要让模型上游拉取本地上传的参考素材，还需要把 `PUBLIC_BASE_URL` 设置为公网可访问的站点地址。

## 批量生产 Worker

正式环境先配置 MySQL 或 PostgreSQL、七牛 Kodo、后台默认图片模型及对应计费规则，再启动独立 Worker：

```bash
docker compose --profile worker up -d
```

Worker 默认使用内置标准执行器：根据任务创建时固化的品牌、商品和 SKU 快照组装生产模板，普通任务调用默认图片模型的生图接口，有参考图时调用多图编辑接口；生成结果完成校验后归档到企业 Kodo 空间，并沿用生成任务的预扣、成功结算和失败退款规则。

如需使用自有生产服务，可同时配置 `BATCH_WORKER_EXECUTOR_URL` 和 `BATCH_WORKER_TOKEN` 切换到外部执行器模式。外部执行器必须按请求中的 `Idempotency-Key` 幂等处理，并返回 `resultUrl`、`mimeType` 和 `size`。
